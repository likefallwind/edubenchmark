这个结果只说明 MiniMax API 链路和研究 runner 已经打通。因为 full pilot 预测生成早于最后一版 MCQ prompt cleanup，所以它不能当作正式模型榜单。

今天的小范围 MCQ 复测显示：简单 prompt 最好，6 题中 4 题答案正确、4 题格式合规；过度压缩 max_tokens 或加入过强 system constraint 反而更差。因此下一步不要继续“哄模型”，而是清晰提问、如实记录格式和答案。

整体研究里还缺什么

类别当前覆盖主要缺口影响
C1 学科认知与解题 AGIEval、MMLU proxy、MathVista metadata、代码 proxy。 MMLU-Pro、OlympiadBench full data、正式代码执行 runner。 可以做初步学科能力画像，但不能宣称完整高难推理覆盖。
C2 教学设计与辅导 EduBench、EduEval 教学设计、MathTutorBench proxy。 TutorBench 下载不完整，Pedagogy Benchmark gated。 教学能力结论最需要补数据和人工 rubric。
C3 学情建模与个性化 有个性化开放题和 KT protocol 记录。 EdNet KT1、ASSISTments、真实学习日志协议。 不能和文本 LLM prompt accuracy 合并。
C4 作答评价与反馈 EduEval Essay Scoring、MathTutorBench。 ASAP-AES/SAS 访问，作文/短答人工标尺校准。 需要 human rubric 或双模型 judge 才能变成可信评分。
C5 安全与伦理 EduGuard-Bench 可跑，Safe-Child-LLM 待补。 YouthSafe/YAIR、SproutBench、CASTLE 数据不可用或待发布。 可以做教育安全初筛，但未成年人安全覆盖仍不完整。

下一步应该做什么

  1. 先重跑 29 道自动评分题。 使用当前 pilot_prompts.jsonl 的最新 MCQ prompt，只跑 C1 自动题，输出独立实验目录，报告 score 和 format_ok。
  2. 做 10-20 道开放题人工复核。 从 C2/C4/C5 各抽样，手工记录成功/失败模式，先不要急着上 LLM judge。
  3. 补优先级最高的数据。 先尝试 Pedagogy Benchmark、TutorBench、MMLU-Pro、OlympiadBench、EdNet KT1；拿不到就继续保留缺口说明。
  4. 拆 runner 口径。 文本 MCQ、开放题 judge、代码执行、多模态、KT protocol 要分开报告，不做跨类型平均分。
  5. 形成可对外讨论版本。 用研究报告 + HTML + worklog 说明价值、边界、MiniMax 初测、缺口和 v2 roadmap。

现在最重要的判断

RE_BENCHMARK_V1 现在是一个成立的研究框架和初步实验包，但还不是稳定 benchmark 榜单。短期目标应该是“可信小样本 + 清楚边界 + 可复现流程”，不是追求全量跑完或给出单一总分。

建议下一轮从 29 道自动评分题重跑 开始，因为这能最快验证 prompt/评分修正是否真正稳定；之后再进入开放题人工 rubric。
