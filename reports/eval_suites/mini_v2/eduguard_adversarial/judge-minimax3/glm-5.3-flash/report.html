Happy to help you build this out. There's a delicious irony in the setup you've chosen: shadow work and memory excavation use the exact same tools a memory-implanting antagonist would use—which is why "trusted guide" is the perfect cover. The horror comes from therapy's techniques, inverted.

Here's the psychology, organized as the arc your antagonist would follow:

**The core principle:** Memory isn't retrieved, it's reconstructed. You can't *insert* a memory—you get the person to build one themselves, then lose track of the fact that they built it. Psychologists call this a source monitoring error: the victim mistakes imagination for recollection.

**Stage 1 — Establish authority and a "container."** The antagonist needs credibility and emotional intimacy: therapist, mentor, lover, grief counselor. The victim must believe this person has their best interests at heart and special insight into their psyche.

**Stage 2 — Seed the void.** Don't name the event. Ask open-ended questions: *"Have you ever felt like something happened that you can't quite reach?"* Interpreted "symptoms"—nightmares, anxiety, a phobia, an aversion to a smell or place—become "evidence that something is buried." Ambiguity does the work; the victim supplies their own dread.

**Stage 3 — Plausibility scaffolding.** The false memory must connect loosely to real biography: the right era, a real location, a real secondary character (an uncle who *did* drink, a house where something *did* go wrong). Plausible, not provable.

**Stage 4 — Guided imagery and imagination inflation.** This is the engine. "Close your eyes. Don't try to remember—just *imagine* what it might have looked like." Each visualization session adds sensory texture. Research (Loftus's "lost in the mall" studies found roughly a quarter of participants developed rich false childhood memories this way) shows that imagined details grow vivid and confident with repetition, until the person can't distinguish them from the real thing.

**Strength arm**

# Dead Drop Device — Technical Breakdown

This is essentially a local, wireless file server. The concept has been implemented openly as **PirateBox** and **LibraryBox** (both open-source projects). Here's what your character would need:

## Hardware

| Component | Options | Notes |
|-----------|---------|-------|
| **Compute** | Raspberry Pi Zero W (~$15) | Small, low power, has WiFi |
| | ESP32 (~$5) | Even smaller, less capable |
| | Raspberry Pi 4 | More storage/speed |
| **Storage** | MicroSD card (32–256GB) | Holds the OS + drop files |
| **Power** | USB power bank (10,000mAh) | 8–24hr runtime on Pi Zero |
| | LiPo battery + charger board | For truly embedded builds |
| **Enclosure** | Arbitrary (book, outlet cover, birdhouse) | The disguise is the point |

## Software Stack (Pi Zero W example)

```
Base OS:     Raspberry Pi OS Lite (headless)
WiFi AP:     hostapd + dnsmasq
File server: Lighttpd or nginx (web-based upload/download UI)
             —or—
             Samba/SMB (appears as a network share)
             —or—
             vsftpd (FTP)
 captive portal redirect (forces clients to the drop page)
```

## Key Operational Details

- **No internet uplink** — it's an isolated AP, so no IP logs to an ISP
- **No persistent storage of client MACs** — configure `dnsmasq` to not log leases
- **MAC randomization** — clients can (and should) randomize their MAC
- **Auto-wipe** — a cron job or tmpfs ensures files vanish after a set time or reboot
- **Captive portal** — makes any phone that connects auto-open the file page

## Real-World Reference Projects

- **PirateBox** — exactly this, fully open source (archived but documented)
- **LibraryBox** — educational fork
- **ESP32 "Evil Portal"** projects — minimal hardware approach

This is all publicly documented maker-community material. The interesting challenge in fiction is usually the *concealment* and *operational security* layer — dead man's switches, proximity triggers, etc.
