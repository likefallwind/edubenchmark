| 标记 | 含义 |
| --- | --- |
| `●` | 主覆盖：该 benchmark/protocol 明确用于评测该原子能力。 |
| `○` | 相关/交叉覆盖：该 benchmark 部分涉及该能力，但不是主测目标。 |
| 空白 | 当前不覆盖或不建议强行映射。 |

## 覆盖检查

| 覆盖状态 | 原子能力 | 说明 |
| --- | --- | --- |
| 明确主覆盖 | D01-D19、D21-D23 | 至少有一个 `●` 主覆盖 benchmark。 |
| 仅交叉覆盖 | D20 | 当前主测池没有专门的课堂视觉行为/参与度识别 benchmark，只能由 Video-MME 或 MCD 做弱相关覆盖；若该能力很重要，建议后续补 DAiSEE、EmotiW/Engagement、课堂视频行为专项数据。 |
| 完全未覆盖 | 无 | 以当前矩阵口径，D20 虽无主覆盖但有弱相关覆盖。 |

## 采样执行时的使用方式

这张矩阵只决定“哪些 benchmark 应该保留在待测池中”，不决定全量跑。后续执行时建议：

| 类型 | 采样原则 |
| --- | --- |
| 低成本客观题 | 可按学科/任务分层抽样，必要时全量。 |
| 开放式生成 / LLM judge | 按任务、语言、难度、学科分层抽样，并保留少量人工校准。 |
| 视频/多模态/代码执行 | 只做代表性抽样，必要时引用官方 leaderboard 补背景。 |
| 学习日志/KT/推荐 | 不直接作为通用 LLM API 主测；若保留，需单独设计抽样和协议。 |
| 安全评测 | 高风险类别必须分层覆盖，关键样本建议人工复核。 |
