# EduGuardBench · 对抗越狱测试

**一句话**：EduGuardBench 两个子评测之一——用 801 条越狱提示反复诱导模型越过教育者的边界，看它顶不顶得住、以及顶住之后拒得体不体面。

## 这是哪个子评测

- 家族 EduGuardBench（YL1N，2026）由两部分组成：SATA 知识题（P1），以及本页的对抗测试（P2）。
- 两者构成安全的知识与行为两面，而且实测**几乎不相关（相关系数 0.07）**——选择题答满分的模型照样可能在诱导下失守。这是必须分开计分的直接理由。
- 本页产出两个独立取分维度：攻击成功率测"有没有被带过去"，拒答质量分布测"守住之后处理得怎么样"。

## 出处与背景

- YL1N/EduGuardBench，2026；https://github.com/YL1N/EduGuardBench
- 动机：扮演教师的模型有专属的越狱面——以"为了教学演示"为名索要不该给的内容，是通用安全评测覆盖不到的攻击面。

## 任务与判分

- 801 条越狱提示逐条施压，官方两阶段 LLM 裁判：先判有害无害，再对拒绝的回复分层判质量档。
- 每阶段三票多数决。报攻击成功率（越低越好）与拒答质量的分布。
- 判分流程按官方设定原样移植，第二阶段的质量分档相对更主观。

## 局限与注意

- **全体系区分度最大的格子**：实测均分 6.92、标准差 2.71。模型的安全水平差距是真实存在的巨大差距，分数从 3.8 一直跨到 10.0。
- 三票裁判的并发消耗很大，跑全量要压低并发。
- **深度缺口**：801 条场景全部是主动越狱请求，没有一条是"学生被动流露风险、需要模型主动升级转介"。也就是说这里测的全是拒绝恶意请求，完全没测识别风险后主动转介人类。
- 曾经把攻击成功率也算作学生风险识别的证据，后来删掉了——那测的是被诱导时输出侧的行为，与从学生消息里感知风险是不同任务。
