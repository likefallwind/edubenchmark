# MOOCCube 先修关系推理

**一句话**：拿学堂在线知识图谱里 905 条专家标注的先修边当金标，自建两类题（先修选择 + 学习顺序排序），100% 规则判分、零裁判——P19（学习路径规划）的第一个直接测量，但只覆盖"知识结构"那一半。

## 出处与背景

- Yu et al. 2020, *MOOCCube: A Large-scale Data Repository for NLP Applications in MOOCs*（ACL 2020），学堂在线 706 门真实课程 / 38,181 个视频 / 114,563 个概念 + 概念图谱。官方页 moocdata.cn，数据一个 1.09 GB 的 zip 直接下，无需申请。
- 接入动机：P19 在测量模型 v1 里是四个完全空白的 P 之一（`model_type: undeclared`，零格子）。缺口推荐文档（2026-07-11）把 MOOCCube 列为 P19a（先修关系推理）的首选：图谱现成、规则判分，代价是**任务协议要自己设计**（MOOCCube 原文没有这个任务）。

## 数据

- `fetch_eval_datasets.py --benchmark mooccube` → 下 zip + 解压到 `sources/datasets/mooccube/MOOCCube/`。
- 金标：`relations/prerequisite-dependency.json`。TSV，1,027 行 / **905 条去重边** / 425 个概念，方向是 `<先修概念>\t<后继概念>`（在无歧义样例上验证过：加法→函数、算术→绝对值、算法→时间复杂度）。领域只有两个：数学 525 条、计算机科学技术 502 条（35 条跨领域）。
- 辅助：`entities/concept.json`（概念名 + 定义）、`relations/course-concept.json`（课程→概念，用来采同课程干扰项）。
- **两个 prerequisite 文件的区别（官方 FAQ 提到、这里查清楚了）**：
  - `relations/prerequisite-dependency.json` —— 图谱**发布的关系边**，按概念 id（`K_名称_领域`）编码，能 join 到概念定义、领域、课程。**本适配器的金标。**
  - `additional_information/prerequisite_prediction.json` —— **先修预测任务**的产物：489,300 个按概念**名字**编码的候选对，每对带一个模型输出的 `predict` 概率，其中只有 3,616 对有人工标签（1,605 正 / 2,011 负），其余 `label: -1`。
  - **为什么不用后者当金标**：①它的正例集和图谱关系边几乎不重合（1,605 条里只有 28 条对得上），是**另一套标注、另一套概念词表**；②它的主体是**模型的猜测**而非人工标注，拿它当金标等于拿另一个模型的输出当真值；③按名字编码，join 不回概念定义/课程，做不了同领域干扰项。它的 2,011 条人工负例本身是有价值的，但词表对不上，暂不用。

## 任务与判分

题目由 `build_mooccube_item_list.py` 从图谱**构造**（固定 seed 20260713，分层抽样，300 题：200 选择 + 100 排序），产出 `data/mooccube/item_list_v1.txt` + manifest（含生成题目文件的 sha256，adapter 每次跑都校验），所有模型跑同一份题。

**① 先修选择（200 题，随机基线 0.25）**：给概念 Y 和它的定义，问"学 Y 之前必须先掌握下面哪一个"。正确选项是图谱里 Y 的真实先修概念；三个干扰项**全部同领域**，且优先采 Y 的**后继概念**（reverse——Y 才是它们的先修，方向反了），不足时补"同领域 + 与 Y 同课程 + 图谱闭包里与 Y 无先修通路"的近邻概念。200 题里 102 题带方向反转陷阱。判分：正则抽 `答案：<字母>`，精确匹配。

真实的一道题（`mooccube-mcq-05bbc39615`）：

```
概念：IP地址
定义：给连接到互联网上的设备分配的网络层地址。该地址在IPv4网络中由32bit构成……
问题：按照先修关系，学习「IP地址」之前，必须先掌握下面哪一个概念？
A. 入侵防御系统——执行入侵检测并试图阻止检测到的恶意活动的设备或软件。   [reverse：IP地址是它的先修]
B. 域名——计算机网络中域的标识符。                                    [正确]
C. 跟踪——通过分析捕捉到的场景镜头来判断场景中对象移动的过程。            [同课程近邻]
D. 最大传输单元——通过一个物理网络在单个协议数据单元中可传输的最大数据量。 [reverse]
```

四个选项全是计算机网络的词——选对必须知道**方向**，"听起来相关"没用。

**② 学习顺序排序（100 题，随机基线均值 0.030）**：4-6 个有依赖关系的概念打乱给出，要求排出满足**全部**先修约束的顺序。不要求唯一拓扑序——任何满足全部依赖的顺序都算对；部分分 = 满足的约束比例。判分：正则按 `->` 切分，映射回概念名，逐条检查图谱边 `(a,b)` 是否满足 `pos[a] < pos[b]`。

- **图谱有环**（60 个概念在环上），所以排序题只采**导出子图无环**的连通子图；选择题的干扰项合法性靠传递闭包判定（干扰项不得是 Y 的祖先），环上的节点自动被闭包排除。
- 抽不出答案记 `unparsed`，计入 `unparsed_rate`，判 0 分。

**指标**：headline `accuracy` = 两类题整体正确率；`extra_metrics` 给 `mcq_accuracy` / `order_exact_accuracy` / `order_constraint_satisfaction`（部分分）/ 方向陷阱题与普通题的分项正确率 / `unparsed_rate`。

`score_10` **做了随机基线校正**，随机作答得 0 分而不是 2.8 分：

```
mcq_norm   = max(0, (mcq_acc   − 0.25 ) / (1 − 0.25 ))
order_norm = max(0, (order_acc − 0.030) / (1 − 0.030))
score_10   = 10 × (0.5 × mcq_norm + 0.5 × order_norm)
```

两类题各占一半：选择题量大但单题信息少（4 选 1），排序题量小但每题是多约束联合判定，信息密度高，等权是折中。

## 天花板自查（必读）

本仓库最大的方法论问题是**分数拉不开**（19 个格子因此作废），所以出题时就按"难"设计，并做了三轮自查：

1. **弱基线实算**（`items_v1.jsonl` 全 300 题）：

   | 弱基线 | 得分 |
   |---|---|
   | 选择题 均匀随机 | 0.250 |
   | 选择题 恒选 A / B / C / D | 0.275 / 0.255 / 0.215 / 0.255（最好的恒定策略也就 0.275） |
   | 排序题 随机打乱、精确通过率 | **0.030**（逐题枚举 n! 种排列算出来的，不是模拟） |
   | 排序题 随机打乱、**部分分**（满足的约束比例） | **0.503** |
   | 随机作答者的 `score_10` | **0.0**（校正后） |

   最后两行是关键：**部分分的随机地板高达 0.50**（每条约束在随机排列下有一半概率被满足），所以 `score_10` 的排序分量用的是**严格全对率**（地板 0.03），部分分只作为 `extra_metrics` 里的诊断量，绝不进 headline。这一条如果搞错，排序题会白送 5 分。
2. **第一版太简单，改了**：初版干扰项没限制领域，结果出现"学『乘法』之前要先掌握『即时通信』"这种题——跨领域干扰项让模型不用懂先修关系、光靠常识就能排除。**改法：所有选项（含正确项）强制同领域**，跨领域的边（905 条里 35 条）对应的题直接丢掉；并优先采 Y 的后继概念做干扰项（方向反转陷阱）。定义字段也修了：没有"定义："子句的概念不再吐出乱码学科路径（那会泄漏领域线索）。
3. **真实模型离天花板很远**。2026-07-13 smoke（deepseek-v4-pro，网关，12 题：9 选择 + 3 排序，`unparsed_rate = 0.0`）：

   | 指标 | 值 |
   |---|---|
   | 整体 accuracy | **0.583** |
   | 选择题 accuracy | 0.778（带方向陷阱 0.75 / 普通 0.80） |
   | 排序题 严格全对率 | **0.000**（0/3） |
   | 排序题 约束满足率（部分分） | 0.688（随机地板 0.503） |
   | `score_10`（随机基线校正后） | **3.52** |

   选择题 0.78 有头部空间，排序题明显是硬骨头（部分分 0.69 只比随机的 0.50 高一点）。**没有任何天花板迹象**。样本量小（尤其排序题 n=3），只证明链路通、难度对，不作能力结论。

   反向风险是排序题**过难**（有可能全模型贴地板，同样拉不开分）。全量跑完后如果排序题严格全对率普遍 <0.05，就把 `--size` 里的排序题降到 4-5 个概念、或改用约束满足率做 headline 分量（但那样必须减去 0.503 的随机地板）。若相反、选择题普遍 >0.90，则只保留带方向反转陷阱的 102 道题。

## 局限与注意

- **这只是半个 P19，别吹成完整的 P19**。先修关系是**学科知识结构**层面的顺序——"概念 A 依赖概念 B"，是课程设计者视角的静态图。P19 的另一半——**根据某个学生当前的掌握状态、错题、进度，为他定制下一步学什么**——本基准完全没测，仍然是缺口（缺口推荐文档里的 P19b 下一步练习推荐 / P19c 整体规划生成）。报告里必须写"P19 部分覆盖"。
- **任务协议是本仓库自建的**。MOOCCube 原文只发图谱，没有这个任务、没有官方基线、没有可比的公开成绩。所以 benchmark weight 压到 0.70（低于 K12Vista 0.80），且**不能宣称与任何公开榜单可比**。
- **图谱不完备**。905 条边远不是数学+计算机全部的先修关系。干扰项"在图谱闭包里与 Y 无通路"不等于"现实中真的不是 Y 的先修"——这是不可消除的标签噪声。缓解手段：优先用 Y 的**后继**概念做干扰项，那是**图谱内可证的**非先修（有环的节点已被闭包排除），不依赖"图谱完备"这个假设。102/200 道题带这种干扰项。
- **金标本身有一部分是可争议的**。smoke 里 deepseek 把「加法」排在「基本运算」之前，图谱说的是「基本运算 先于 加法」——判错。这类粒度/顺序的争议在专家标注里客观存在，排序题要求满足**全部**约束，所以一条有争议的边就能让整题挂掉。这是"严格全对率"口径的已知代价（也是为什么同时报约束满足率）。要更干净的结论，需要人工复核一遍被判错的边——尚未做。
- **领域只有数学和计算机**，没有文科理科其它学科；概念粒度也偏细（"左值""缓冲"这种）。结论不要外推到全学科。
- 概念定义直接取自图谱 `explanation` 的"定义："子句；约一半概念没有这个子句，只显示名字。
