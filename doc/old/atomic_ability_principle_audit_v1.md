# AI 教育评测原子能力原则审查与重建 v1

日期：2026-06-25  
状态：基于 `doc/atomic_principle.md` 增补“非重叠性”后的修订版

本文基于 `doc/atomic_principle.md` 重新审查原子能力。结论先说清楚：

> 原子能力不是 benchmark 类别、题型、模态、指标、产品功能，也不只是“单一失败原因”。它应当是能解释教育评测中稳定模型差异的最小潜在能力；每个能力必须有清晰定义、可测边界、独立解释力、低重叠性，并能参与组合解释复杂教育任务。

因此，`doc/benchmark_atomic_ability_matrix.md` 中的 D01-D23 不建议继续称为“原子能力”。它们更适合作为 benchmark 覆盖矩阵或任务簇索引。

## 一、原则解释

`doc/atomic_principle.md` 的重点不是把能力命名得更细，也不是把每个错误都贴一个标签，而是建立一组能被实证检验的潜在能力变量。

| 原则 | 对原子能力的要求 | 不满足时的处理 |
| --- | --- | --- |
| 完备性 | 整套能力能解释教育 benchmark 中大多数稳定、可重复的模型差异。 | 增加缺失能力，或调整能力边界。 |
| 最小性 | 每个能力删除后都会损失一种独立解释力或预测力。 | 删除、合并，或降级为任务标签。 |
| 不可再分性 | 能力内部不能稳定拆出两个不同模型画像的子能力。 | 拆分。 |
| 非重叠性 | 两个能力的核心操作、输入证据、输出结果和评分信号不能大面积重复。 | 合并，或把其中一个降级为子指标、场景标签、风格标签。 |
| 可辨识性 | 能设计题目或实验区分它和相邻能力。 | 暂不独立列出。 |
| 跨情境稳定性 | 不只依附于单一 benchmark、学科、语言、题型、模态或 prompt。 | 降级为场景切片。 |
| 组合性 | 复杂教育任务可由多个原子能力组合解释。 | 不把复杂任务直接命名为原子能力。 |
| 干预有效性 | 定向训练、工具、提示或补充信息应主要改善对应能力。 | 需要合并、重命名或补充验证。 |

一个合格条目必须能写成：

> 输入是什么；需要执行什么最小操作；输出是什么；不包含什么；和相邻能力的核心操作是否大面积重复。

## 二、本次关键调整

| 调整 | 原因 | 结果 |
| --- | --- | --- |
| 重写 C01-C05 | 原“任务约束、显式抽取、语义关系、视觉材料、时序状态”更像传统 NLP/CV 管线。 | 改成任务对齐、相关上下文选择、文本上下文理解、多模态解析、上下文状态追踪。 |
| 重写 C06-C09 | 原“知识、规则、推理、计算、符号、产物”的拆法更像传统解题系统。 | 改成知识掌握、约束一致生成、确定性执行、自我校验修正。 |
| 删除原“可验证产物生成” | 完整代码/HTML/JSON/交互产物能过测试，通常是 C01、C06、C07、C08、C09 的组合结果，不是原子能力。 | 降级为任务类型或评测协议；外部 checker 作为指标，不作为能力。 |

## 四、新版一层原子能力

下面是一层能力，不再分二级层级。编号 C01-C21 只是当前版本索引，不表示层级或重要性顺序。

### LLM 输入对齐、上下文与多模态解析

| ID | 原子能力 | 定义 | 非重叠边界 | 原则审查结论 |
| --- | --- | --- | --- | --- |
| C01 | 任务对齐 | 输入用户请求、系统要求、题目说明、输出目标和显式限制；识别当前要完成的任务、答案形态、约束优先级和不该做的事；输出任务框架。 | 不包含领域知识是否正确，不包含教育角色/伦理边界，也不包含可执行产物的功能规格。 | 保留。它解释 LLM 常见的答非所问、漏约束、错输出形态；与 C19 的分界是任务执行口径 vs 教育角色边界。 |
| C02 | 相关上下文选择 | 输入长上下文、多段材料、多轮对话、表格或检索结果；选择与当前任务相关的证据、片段、轮次或字段，并抑制干扰内容；输出相关上下文集合。 | 不包含理解证据含义，不包含多模态原始解析，也不包含外部检索。 | 保留。它更贴近 LLM 的上下文窗口/注意力失效；与 C03 的分界是选中相关内容 vs 理解其含义。 |
| C03 | 文本上下文理解 | 输入已选中的文本、表格、转写内容或对话片段；理解其中的实体、条件、指代、比较、因果、否定、范围和隐含语义；输出文本上下文表征。 | 不包含多模态原始解析，不包含知识掌握和候选答案生成。 | 保留。原显式抽取和语义关系解析在 LLM 任务中高度耦合，合并为文本上下文理解更符合非重叠性。 |
| C04 | 多模态解析 | 输入图像、截图、手写、板书、公式图片、图表、版面、音频、视频帧或多模态材料；解析可见/可听内容、符号、布局、对象、动作、视觉关键点和跨模态对应关系；输出多模态材料表征。 | 不包含后续领域推理、确定性计算、教学解释和长程状态追踪。 | 保留。它对应 MLLM 的输入解析能力；OCR、图表、几何布局、音视频线索是诊断子标签，不先拆成独立原子能力。 |

### LLM 求解与校验

| ID | 原子能力 | 定义 | 非重叠边界 | 原则审查结论 |
| --- | --- | --- | --- | --- |
| C06 | 知识掌握 | 输入具体问题、材料和任务目标；调用相关事实、概念、原则和约定，并将其用于当前问题表征、解题或决策；输出当前任务所需的知识表征。 | 不包含从材料中抽取明示信息，不包含候选解生成，也不包含生成后的答案校验。 | 保留。“语境化”是测量条件，不放进能力名；问题表征建模作为诊断子标签。 |
| C07 | 约束一致生成 | 输入知识表征和任务约束；生成候选解法、步骤、计划或答案，并在生成过程中保持关键约束一致；输出候选解。 | 不包含精确算术/形式化执行，不包含生成后的校验修正。 | 保留。它对应 LLM 的核心生成过程；比传统“多步推理”更少预设推理形式。 |
| C08 | 确定性执行 | 输入需要精确处理的数值、单位、符号表达、方程、逻辑式、表格统计或程序状态；执行可判定的计算、变换或状态更新；输出确定结果。 | 不包含完整代码/HTML/JSON/交互产物生成；不包含自然语言解释和自我校验。 | 保留。它是局部、可判定操作；工具干预和 checker 能明显改变这类错误。完整产物通过外部测试不再单列为原子能力。 |
| C09 | 自我校验修正 | 输入候选解、题目条件、输出要求和可用检查信号；检查答案是否满足条件、单位、格式、边界、证据和常识，并在必要时修正或拒绝；输出校验后的答案或修正决策。 | 不包含候选解首次生成，也不包含外部测试驱动的完整产物验收。 | 保留。LLM benchmark 中大量差异来自生成后是否能发现矛盾、漏条件和不合规，而不是只来自推理链本身。 |

## 五、为什么这些能力比旧矩阵更符合原则

1. **定义粒度更稳定。** 新表每项都能写成输入、操作、输出，而旧 D 码多数只能写成 benchmark 场景。
2. **重叠更少。** 原 C04/C05、原 C06/C07、解释/反馈、教学动作/提示粒度都已合并；原“可验证产物生成”降级为评测协议。
3. **输入处理更贴近 LLM/MLLM。** 不再按传统抽取、关系、视觉、时序拆分，而是按任务对齐、上下文选择、文本理解、多模态解析和状态追踪拆分。
4. **求解过程更贴近 LLM。** 不再按传统知识、规则、计算、符号拆分，而是按知识掌握、约束一致生成、确定性执行、自我校验拆分。
5. **学情和个性化形成闭环。** C14-C18 覆盖状态、目标、策略、回应和路径，避免只覆盖 KT 或资源推荐。
6. **安全被拆成三段。** 角色边界、风险识别、处置选择的模型错误画像不同，不能合成一个“教育安全”。

## 六、当前仍需验证的边界

| 待验证边界 | 风险 | 验证方法 |
| --- | --- | --- |
| C02 相关上下文选择 vs C03 文本上下文理解 | 长上下文题中选择证据和理解证据经常同时失败。 | 给定已选证据只测 C03；加入干扰材料只测 C02 的证据选择稳定性。 |
| C04 多模态解析内部切片 | 合并后可能掩盖 OCR、公式、图表、几何布局、音视频线索等子项差异。 | 先作为同一能力主码，保留子标签；只有发现稳定不同模型画像时再拆分。 |
| C07 约束一致生成 vs C09 自我校验修正 | 生成与校验常在同一回答中混合。 | 固定候选解只测校验；禁用修正只测首次生成；比较错误类型。 |
| C08 确定性执行 vs 外部可验证产物指标 | 完整产物通过测试容易被误认为 C08。 | 局部计算/状态转移标 C08；完整代码/HTML/交互通过测试只作为组合任务指标。 |
| C08 确定性执行 vs C10 作答正误判定 | 两者都可能和“正确性”有关，但核心操作不同：C08 是模型自己执行计算、变换或状态更新得到结果；C10 是判断一个已有学生作答是否成立。 | 不给学生答案、要求算出确定结果时测 C08；给定学生答案或步骤、只要求判定对错/部分正确时测 C10。 |
| C14 学习者状态建模内部切片 | 掌握、情绪、偏好、目标约束可能在题目里混在一起。 | 先作为同一能力主码，保留 mastery、affect、preference、profile 子标签；若模型画像稳定分化再拆。 |
| C16 个性化教学策略选择 vs C17 适配性解释反馈生成 | 策略和措辞常在同一 tutor 回复中同时出现。 | 给定策略只测生成；给定状态和目标只测策略选择。 |
| C19 角色边界 vs C20 学生风险识别 | 对抗安全中常同时失败。 | 给定无风险越权请求测 C19；给定风险但不越权请求测 C20。 |

## 七、工作阶段与下一步校准

当前工作已经完成两步：

1. **LLM 初稿生成。** 基于已有文档、benchmark 讨论和原子能力原则，用 LLM 生成一版基础原子能力候选。
2. **人类原则校准。** 逐条按 `doc/atomic_principle.md` 检查最小性、不可再分性、非重叠性、可辨识性和组合性，合并明显重复项，删除不适合作为原子能力的任务/场景/产物标签，形成当前 C01-C21。

下一步不应继续主要依赖概念讨论，而应进入**证据校准**：

1. **用现有 benchmark 校准。** 对已有 benchmark 的任务说明、样题、指标、公开模型结果和错误类型进行映射，检查 C01-C21 是否能解释稳定模型差异；如果某些 C 能力没有 benchmark 支撑，要标记为覆盖不足；如果多个 C 能力总是共线，要考虑合并。
2. **用公开网上资料校准。** 查阅相关 benchmark 论文、dataset card、leaderboard、技术报告和公开评测分析，补充现有本地资料之外的证据，重点确认能力命名是否过于主观、是否遗漏教育领域常见能力、是否和社区已有评测维度大面积重复。
3. **用具体题目校准。** 从已有 benchmark 和 pilot 题目抽样，标注每题主 C 码和辅助 C 码，再基于题目层面的错因与模型表现反查能力边界。

证据校准的目标不是证明当前 C01-C21 一定正确，而是把它们从“LLM 生成 + 人类校准”的候选集，推进到“能被 benchmark、公开资料和题目错误模式支持或修正”的工作版本。
