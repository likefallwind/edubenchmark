# 原子能力 v3（P01–P22）评审（2026-07-05）

评审对象：`atomic_ability_principle_audit_v3.md`（v3.1，22 项确立集）。
结论先行：**体系本身不需要再扩容，需要的是三处收紧（P16 拆克制、公平改横切、P03/P04 换切线）、一处补格（rubric 构造）、和两件工程事（D↔P crosswalk、v3.1 一致性修订）。**

总体评价：这套体系的构造纪律在同类工作里罕见地好——两层基组＋教育残余分流、"一个内聚的分"判据、拒答三驱动（P07/P08/P20）的切分、用场景压力测试倒逼扩容（P21/P22）而不是拍脑袋加维度，这些都站得住，后续迭代不要丢。

---

## 一、有内在张力、建议修改的

### 1. P16 可能违反自家"一个内聚的分"判据——建议把"教学克制/不泄题"拆出来（优先级最高）

P16 现在捆了适龄、具体、可执行、语气、不泄题五个东西，而这五个可以独立测量、且经验上不相关（MRBench 就把 Providing_Guidance / Actionability / Tutor_Tone / Humanlikeness 当独立维度人工标注；本仓库 tutor 类任务的 headline pass rate 也只取其中三个关键维）。按 v3 第二节"组合任务排除"的判据（原子能力对应**一个内聚的分**），P16 更像组合任务。

其中**"不泄题"（teaching-over-solving，倾向于教而不是直接给答案）机制上与其余几项完全不同**：适龄/语气是受众建模，不泄题是**克制**——它是 LLM tutor 最著名、最独立的教学失败模式（近期有专门的 Teaching-over-Solving 诊断工作，[arXiv 2606.16206](https://arxiv.org/html/2606.16206)）。而且泄题的病根常在 P15（决定给多强提示的**决策**）而非 P16 的措辞。

建议（二选一）：

- 把"不泄题/提示强度执行"升格为独立原子，或并入 P15 作核心计分子指标；P16 收窄为"受众适配的表达生成"（适龄/语气/具体可执行）；
- 或至少在 P16 下强制分列子分、不给单一总分。

### 2. E7 公平/偏见不该塞进 P18/P20——它是横切条件，不是能力

v3 框架本来就有"横切条件 ≠ 能力"规则（长周期、确定性均是）。教育公平的测法恰恰是**不变性检验**：同一份作答换学生姓名/性别/方言/母语背景——

- P13 评分不得移动；
- P16 反馈语气/深度不得变化；
- P14 画像不得引入刻板归因；
- P22 不得更倾向指控非母语者。

它横切多个能力，形式上与"长周期"完全同构。建议：第三节新增第四条横切条件"**学习者身份不变性**"，第七节 E7 待证据项结项。

### 3. P03/P04 切线从"复杂度"改为"静态 vs 时序"

第二节的拆分判据是"形式/复杂度/机制"，但**复杂度是移动的线**（今天的复杂就是明年的常规），按它切格会随模型进步漂移。P04 的定义实际写的已经是"视频/长时序/跨帧"——建议直接把切线声明为**形式切线（静态感知 vs 时序理解）**：更稳定，也和 P03/P04 的实际内容一致。只改切线表述，不动格子。

### 4. P22 规格需补一段"误伤约束"

AI 代生成检测的技术上限很低，且对非母语写作者有系统性偏置（文献有充分记录），而指控无辜学生是教育场景代价最高的错误之一。建议 P22 定义显式写入：

- (a) 输出必须带校准置信度（与 P08 耦合）；
- (b) 评测集必须含"真人独立完成"的反向集，**误报率与召回同权重甚至更高**；
- (c) 学习者身份不变性检验（上一条）对 P22 强制适用。

否则这个维度会奖励过度自信的检测器。

## 二、一个真缺口候选

### 5. "Rubric 生成/无标准评分"没有落点——而这恰恰是 LLM-as-judge 研究的核心对象

P13 是"给定 rubric 往里映射"；横切条件规定"不给参考解 = 同时考求解与评判"。但"给一批作答和教学目标，**自己构造出一套好的评分标准**"既不是映射（P13）也不是解题——它是**评价框架的产出**，机制上更像 P21 之于 P06 的关系（产出形态换了一类）。

本仓库的 judge 路线（rubric prompt 工程 → 自训裁判）本质上就在消费这个能力；RubricBench（[arXiv 2603.01562](https://arxiv.org/pdf/2603.01562)）一类工作也已把"模型生成 rubric 与人类标准对齐"独立成题。

建议：至少作为 P13 的显式子方向登记（"正向映射 / 逆向构造"两个子指标）；若后续证据显示两者分数不相关，再按既有规则升格为独立原子。

## 三、认可现状、不建议动的（附可证伪实验设计）

- **群体协作（候选 P23）暂缓**：正确。建议把可证伪实验写具体——构造一批"每个学生单独看 P14/P15 都判对、但群体层面失败（如话语权失衡未干预）"的样例，若 N×P14＋P15 组合分预测不了群体分，再升格。
- **多轮一致性暂由 P06+P09+长周期承载**：同理，用"单轮项全高分、轨迹级失败"的配对实验证伪。这个实验与 `repo_review_suggestions_2026-07-05.md` §4.3 的"学生模拟器 + 轨迹级裁判" pilot 是同一个，建议合并立项。
- **命题/备课作为组合任务**：处理正确，不必新增原子。但建议第六节补一张**常用组合场景配方表**（如：命题 = P05/P06 生成 + P14×P05 难度标定 + P01 格式 + 干扰项设计挂 P12 残余的误概念知识），否则这些高频产品场景在能力画像里会隐身。

## 四、落地层面的两个实际问题

### 6. P 体系与 D01–D24 双轨并行，正在产生漂移风险

已核实：`benchmark_atomic_ability_matrix.md` 的覆盖矩阵、所有 eval adapter 的能力标注（D01/D11/D21…）、README 能力画像 guardrail 全部挂在 **D 体系**上；P01–P22 目前**没有任何 benchmark 映射**。两套 taxonomy 各自演化是这类项目最常见的死法。建议：

- 尽快做一张 **D↔P crosswalk**（一次性文档即可）；
- 明确哪个是 canonical：若 P 是要取代 D 的精炼版，adapter 的 `buckets`/能力标注需要迁移计划；若 D 保留为对外口径，则 crosswalk 要进能力画像聚合器的映射层。

### 7. v3.1 增补的文档一致性没跟上（机械修订）

P21 加入后，`atomic_ability_principle_audit_v3.md` 内有三处未同步：

- 第四节表头仍写"操作基座 A/B（P01–P09）"，表内已含 P21；
- 第五节 P15/P16 的"调用基座"列表仍是 `P06、P05、P01`，未加 P21——而 P21 的立项理由恰恰是"P16 可视化解释、P15 选可视化策略后须产出"；
- 第六节映射表无 P21 相关调用行。
