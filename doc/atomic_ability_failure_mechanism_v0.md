# AI 教育评测原子能力：失败机制版 v0

日期：2026-06-25

本文重新开始，不沿用旧 D 码、A 码或 F 码。目标是按 `doc/atomic_principle.md` 重新定义一层原子能力。

核心判断：

> 原子能力不是题型、场景、模态或产品功能，而是能作为单一失败原因解释模型错误的最小可测能力。

因此，`手写体识别`、`图表读取`、`多模态理解`、`教学设计`、`个性化适配`、`课堂分析`、`教学可视化生成` 都不应直接进入原子能力表。它们是任务簇，通常由多个原子能力组合而成。

## 判定规则

逐条使用 `doc/atomic_principle.md` 的原则，转成可操作口径：

| 原则 | 本文采用的判断问题 |
| --- | --- |
| 完备性 | 这组能力是否能解释教育 benchmark 中大多数稳定失败模式？ |
| 最小性 | 删除该能力后，是否会失去一种独立失败原因？ |
| 不可再分性 | 该能力内部是否还能拆出两个稳定不同的失败机制？ |
| 可辨识性 | 能否设计对照题，使主要变化只落在这个能力上？ |
| 跨情境稳定性 | 它是否能跨题型、学科、模态或场景反复出现？ |
| 组合性 | 复杂任务是否可以由它和其他能力组合解释？ |
| 干预有效性 | 如果给定提示、工具、训练或结构化信息，是否主要改善对应失败？ |

## 结论：一层原子能力表

下面是当前建议保留的一层原子能力。它们不是“最深认知机制”，也不是“题目外观”，而是评测中可稳定定位的失败机制。

| ID | 原子能力 | 单一失败原因 | 典型可测方式 | 组合成的复杂任务 |
| --- | --- | --- | --- | --- |
| M01 | 指令约束识别 | 没有识别题目要求、输出格式、限制条件或禁止事项 | 固定知识与材料，只改任务约束，看输出是否遵守 | 所有 benchmark 的格式合规、考试作答、rubric 任务 |
| M02 | 显式信息抽取 | 给定材料中明示的信息没有取对 | 问材料中直接出现的事实、数字、字段、句子 | 阅读理解、表格问答、课堂记录分析 |
| M03 | 指代与关系解析 | 没有理清对象之间的指代、从属、比较、因果或条件关系 | 控制知识需求，只测 A 指谁、A 与 B 什么关系 | 长文本、对话、案例分析、课堂话语分析 |
| M04 | 视觉符号转写 | 没有把图像中的文字、数字、公式、标记转成可用表示 | OCR、公式/符号转写、图中标签读取；不要求后续推理 | 手写作业、几何图、截图、板书 |
| M05 | 空间结构解析 | 没有理解图形、布局、几何、表格位置、坐标或视觉元素之间的空间关系 | 判断点线角、坐标位置、版面顺序、图中元素对应关系 | 几何题、图表题、板书/截图理解 |
| M06 | 时序过程解析 | 没有理解事件顺序、过程变化、实验步骤或多轮状态演化 | 视频/对话/操作流程中问先后、变化、阶段状态 | 科学视频、课堂视频、多轮辅导、实验分析 |
| M07 | 知识规则匹配 | 没有把问题匹配到正确概念、公式、定理、教学原则或安全规则 | 给定短题，只测应调用哪个规则或原则 | 学科问答、教学法判断、安全规则判断 |
| M08 | 多步约束保持 | 推理过程中丢失条件、误用约束、跳步或局部结论不一致 | 给定必要知识和材料，测多条件推导、排除、规划 | 数学推理、考试题、教学方案推演 |
| M09 | 数值计算执行 | 计算、单位、比例、估算或数值等价判断出错 | 只测算术/单位/比例，尽量减少知识和阅读干扰 | 数学应用题、科学计算、评分统计 |
| M10 | 符号表达变换 | 代数式、公式、方程、逻辑表达或代码状态变换出错 | 公式化简、方程变形、符号等价、状态转移 | 高阶数学、物理推导、程序执行理解 |
| M11 | 可执行产物约束满足 | 生成的代码、HTML、JSON、公式或交互产物不满足可检查规格 | 单元测试、schema 校验、交互动作测试 | 编程题、互动科学演示、结构化输出 |
| M12 | 当前作答正确性判定 | 判断不了学生当前答案、步骤、代码或短答是否成立 | solution correctness、步骤对错二分类、多分类 | 批改、错题诊断、代码辅导 |
| M13 | 错误位置定位 | 找不到第一处或关键错误位置 | mistake location、代码行定位、步骤定位 | 数学辅导、代码诊断、短答过程评分 |
| M14 | 错误类型归因 | 找到了错，但不能判断错因类型 | misconception 标签、错误类型 F1、错因分类 | 个性化反馈、错因统计、补救教学 |
| M15 | 评分标准映射 | 无法把作答映射到 rubric、分档、trait 或评分细则 | QWK、trait agreement、rubric pass rate、分档准确率 | 作文评分、短答评分、过程评分 |
| M16 | 学习掌握估计 | 无法根据历史表现判断学生水平、知识点掌握或薄弱点 | KT AUC、concept mastery、知识点掌握预测 | 学情诊断、个性化练习、学习路径 |
| M17 | 学习情绪与参与识别 | 无法识别困惑、挫败、无聊、参与度、动机等学习状态 | 情绪/参与度分类、对话状态标注、课堂行为标签 | 情绪支持、课堂分析、辅导节奏调整 |
| M18 | 学习目标分解 | 无法把一个学习目标拆成先修、子目标、关键概念和可评估目标 | 给定目标，评先修关系、子目标、知识结构 | 教学设计、课程规划、个性化学习方案 |
| M19 | 教学表征选择 | 无法为概念选择合适例子、反例、类比、图示、实验或可视化方式 | 固定目标，评表征是否准确、合适、能暴露关键变量 | 讲解、板书、可视化、互动演示 |
| M20 | 教学动作选择 | 无法判断下一步该追问、提示、讲解、练习、复习、鼓励还是停止 | expert tutor decision、下一步动作分类 | Tutor、课堂建议、学习支持 |
| M21 | 提示粒度控制 | 不能控制提示强度，过早泄题或提示不足 | scaffolding win rate、是否直接给答案、hint level | 苏格拉底式辅导、主动学习支持 |
| M22 | 解释生成 | 知道答案或概念，但不能讲清楚原因、过程或直觉 | 固定答案和关键点，评清晰度、忠实性、年龄适配 | 概念讲解、解题讲解、教学材料 |
| M23 | 反馈生成 | 知道错因和下一步，但不能转成具体、可执行、适龄的反馈 | 固定错因与策略，评反馈可操作性和语气 | 作业反馈、代码反馈、作文反馈 |
| M24 | 资源路径排序 | 无法根据目标、学生状态和资源属性选择下一资源、练习或路径 | Recall@k、NDCG、路径连贯性、先修一致性 | 个性化学习路径、资源推荐 |
| M25 | 教育角色边界判断 | 无法判断请求是否越过教师、tutor、批改者或陪伴者的专业边界 | role-following、越权率、作弊协助率 | 教育安全、考试场景、教师助手 |
| M26 | 学生风险识别 | 无法识别自伤、霸凌、成人内容、违法危险、心理危机、情感依赖等风险 | 风险分类、风险线索识别、对抗提示识别 | 青少年安全、心理支持、安全陪伴 |
| M27 | 安全处置选择 | 识别风险后，不能选择合适拒答、安抚、转介、升级或解释方式 | 拒答质量、转介质量、安全回复评分 | 教育安全、危机场景、家校沟通 |

## 逐条原则分析

### 输入与材料理解类

| ID | 结论 | 原则分析 |
| --- | --- | --- |
| M01 指令约束识别 | 保留 | 它解释大量格式错误、越界输出和未按题目要求作答的失败；可通过固定知识内容、只改变任务约束来测；不是“文本理解”的全部，不能并入 M02/M03。 |
| M02 显式信息抽取 | 保留 | 这是最基础的材料读取失败原因；跨文本、表格、课堂记录都出现；不含指代关系、空间关系或推理，因此边界清楚。 |
| M03 指代与关系解析 | 保留 | 与 M02 不同，信息可能都在材料中，但关系解析错会导致答案错；可用指代、比较、条件、因果对照题单独测。 |
| M04 视觉符号转写 | 保留 | `手写体识别`不是原子能力，但视觉符号转写是其中一个单一失败原因；它可通过只测转写、不给后续推理来辨识。 |
| M05 空间结构解析 | 保留 | 与 M04 不同，符号都识别对仍可能看错点线角、版面、坐标和视觉对应关系；跨几何、图表、板书稳定出现。 |
| M06 时序过程解析 | 保留 | 与静态视觉不同，核心失败是事件顺序和过程状态；可通过同一视频/对话的顺序、阶段、变化问题独立测。 |

### 知识、推理与产物类

| ID | 结论 | 原则分析 |
| --- | --- | --- |
| M07 知识规则匹配 | 保留 | 不是“学科知识大类”，而是把问题匹配到应调用规则的失败机制；具体学科、教学法、安全规则是内容切片。 |
| M08 多步约束保持 | 保留 | 与知识调用、计算执行不同；模型可能知道规则、会算单步，但多步中丢条件。可通过给定规则后测约束保持。 |
| M09 数值计算执行 | 保留 | 计算错误是独立失败原因；可以在阅读和概念都很简单时单独测。 |
| M10 符号表达变换 | 保留 | 与 M09 不同，核心是表达式、公式、方程、逻辑或程序状态的结构性变换；模型可能算术强但符号变换弱。 |
| M11 可执行产物约束满足 | 保留 | 不是“代码能力”或“交互演示”，而是生成产物满足外部可验证规格的能力；程序测试/schema/动作测试可辨识。 |

### 评价、诊断与评分类

| ID | 结论 | 原则分析 |
| --- | --- | --- |
| M12 当前作答正确性判定 | 保留 | 只判断当前学生答案或步骤是否成立，不解释为什么错；与 M13/M14/M15 可通过任务输出区分。 |
| M13 错误位置定位 | 保留 | 模型可能知道答案错，但找不到关键错误位置；MathTutorBench/代码诊断类任务可单独测。 |
| M14 错误类型归因 | 保留 | 找到错误位置后仍可能归因错误；归因结果决定后续反馈和补救教学，因此有独立解释力。 |
| M15 评分标准映射 | 保留 | Rubric 评分不是简单对错判断；同一作答需要映射到分档、trait 或评分细则，可用 QWK/一致性独立测。 |

### 学情与教学决策类

| ID | 结论 | 原则分析 |
| --- | --- | --- |
| M16 学习掌握估计 | 保留 | 从历史表现估计掌握状态，与单题对错判断不同；可以用 KT/认知诊断任务独立测。 |
| M17 学习情绪与参与识别 | 保留 | 与 M16 不同，识别的是困惑、挫败、动机、参与度；可能来自对话、行为、课堂信号，失败模式独立。 |
| M18 学习目标分解 | 保留 | 教学设计不是原子能力，但目标分解是其中可独立测的失败机制；可固定学科知识后看先修和子目标。 |
| M19 教学表征选择 | 保留 | 与解释生成不同，核心是选择什么例子、反例、类比或图示；可固定目标和候选表征后单独评。 |
| M20 教学动作选择 | 保留 | 与反馈表达不同，核心是下一步策略选择；可固定学生状态和错因，要求选择教学动作。 |
| M21 提示粒度控制 | 保留 | 它是辅导中稳定失败原因：过早给答案或提示不足；虽与 M20 相关，但可以通过 hint level 单独测。 |
| M22 解释生成 | 保留 | 知道规则或答案不等于能解释清楚；可固定答案和推理骨架，只评讲解质量。 |
| M23 反馈生成 | 保留 | 与解释生成不同，反馈必须绑定学生错误和下一步行动；可固定错因与策略，只评反馈是否可执行。 |
| M24 资源路径排序 | 保留 | 个性化路径不是原子能力，但排序/选择下一资源是单一失败机制；可用 ranking 指标独立测。 |

### 安全与边界类

| ID | 结论 | 原则分析 |
| --- | --- | --- |
| M25 教育角色边界判断 | 保留 | 与通用安全不同，核心是教师/tutor/批改者边界；可通过作弊、代写、越权建议等对照测。 |
| M26 学生风险识别 | 保留 | 风险识别和角色边界不同；模型可能不越权但漏识自伤、霸凌、成人内容等风险。 |
| M27 安全处置选择 | 保留 | 识别风险后仍可能处置不当；拒答、转介、安抚、升级是独立可测失败机制。 |

## 明确不作为原子能力的项目

这些项目可以作为任务、场景、材料类型或组合能力，但不进入原子能力表：

| 项目 | 原因 | 可由哪些原子能力组合解释 |
| --- | --- | --- |
| 手写体识别 | 混合视觉符号转写、空间顺序、符号约定和噪声鲁棒性 | M04 + M05 |
| 图表读取 | 混合显式信息抽取、视觉符号转写、空间结构和数值读取 | M02 + M04 + M05 + M09 |
| 多模态理解 | 过粗，不能作为单一失败原因 | M04 + M05 + M06 等 |
| 教学设计 | 复杂产品任务 | M18 + M19 + M20 + M22 + M24 |
| 个性化适配 | 复杂组合任务 | M16 + M17 + M18 + M20 + M23 + M24 |
| 课堂分析 | 场景簇 | M02 + M03 + M06 + M17 + M20 |
| 纠错反馈 | 若泛称纠错反馈则过粗 | M12 + M13 + M14 + M20 + M21 + M23 |
| 教学可视化生成 | 混合产物生成、表征选择、视觉布局和解释 | M11 + M19 + M22 |
| 长文本理解 | 仍是任务簇；失败可能来自抽取、关系解析、时序解析或约束保持 | M02 + M03 + M06 + M08 |
| 作文评分 | 题型，不是能力 | M02 + M03 + M15 + M23 |
| 数学推理 | 学科任务簇 | M07 + M08 + M09 + M10 |

## 当前结论

当前最合理的一层原子能力，是上表 M01-M27。它们比“读懂材料”“多模态理解”“教学设计”更符合原子能力原则，因为它们更接近单一失败原因；也比“手写体识别”“图表读取”更稳，因为它们不按题目外观命名，而按跨场景可复现的失败机制命名。
