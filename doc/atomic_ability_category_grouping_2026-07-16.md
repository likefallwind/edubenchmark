# 原子能力大类划分(2026-07-16)

在 19 项原子能力(定稿见 `doc/atomic_ability_mapping_final_2026-07-15.md`;R17 后 P11/P12/P13 已合并为 P11 错误诊断)之上做一层大类划分,用于报告组织和能力画像展示。每个原子能力只归一个类别,不重复挂。

划分只有两个大类:**模型基础能力**和**教育领域能力**。基础能力是 P01–P09 这批不依赖教育场景就能定义、通用 benchmark 就能测的方向;教育领域能力是剩下 11 项,每一项的内核都带着教育专有的知识、构念或政策,离开教育场景就没法定义。

这层划分继承自 `doc/atomic_ability_principle_audit_v3.md` 的两层基座(A/B 操作基座 → 基础;C/D/E 教育任务基座 → 教育),只做了两处调整,理由见文末。

## 划分总表

### 一、模型基础能力(8 项)

| 子类 | 能力 | 归类理由 |
|---|---|---|
| **1.1 输入理解与遵循** | P01 指令与约束遵循 | 对任务和约束的识别与维持,任何领域通用 |
| | P02 长上下文与证据定位 | 长材料中定位证据,教育只是材料来源之一 |
| | P03 多模态理解 | 读图读表是通用感知,学科图表只是对象不同 |
| **1.2 知识与推理** | P05 知识调用与掌握 | 知识调用机制通用;教学专业知识是其中一个 facet,不改变能力本身的性质 |
| | P06 推理与生成 | 解题与约束生成推理,通用 |
| **1.3 输出可靠性(元认知)** | P07 自我校验与修正 | 复查自己输出,通用 |
| | P08 置信度校准与弃答 | 知道自己不知道,通用;但在教育场景后果最重("自信地教错") |
| **1.4 工具与长程执行** | P09 工具使用与长程智能体执行 | agent 能力,通用(暂无挂载) |

## 相对 v3 两层基座的两处调整

1. **P10 从基础侧移到教育侧(2.3)。** v3 把 P10 放在操作基座 B,但它的定义残余——"保证教学产物的教学正确性与可读性"——是教育专有的,和 P18 的"不泄题/适龄/语气"同属教学表达内核。测量上两者也共用 eduillustrate(P10 主格 0.45,P18 产物 facet 0.3),放一个子类里互相印证。
2. **P18 从 v3 的 D 组(认知建模与教学规划)拆出,与 P10 合成"教学生成与表达"(2.3)。** D 组剩下的 P16/P17/P19 是"判断学生是谁、该教什么、按什么顺序教"的决策链;P18/P10 是"把决策变成学生能吸收的表达"的生成链。拆开后两个子类各自内聚。若更看重与 v3 结构的一致性,备选方案是保持 P16–P19 一组、P10 单独成类,不影响大类归属。

P04 不出现:定稿清单已将其并入 P03(难度用证据标签表达,不是构念维度)。

2.1 与 2.2 的边界(R17 后仍然清晰):P11c 错因归因是**从作答内容**解释这一次错在哪(证据源是当前作答),P16a 知识状态估计是**从交互历史**判断学生整体会什么不会什么(证据源是历史记录)——longtutor_diagnosis 的裁决(P16a 主挂、P11c 副挂)就是按这条线划的。

安全三 P(P20/P21/P22)核对过不需要类比 R17 合并:三项残余各自独立(角色规范/风险体系/处置政策),专业标准区分"识别"与"处置"两种胜任力;它们的问题是测量数据同源(R10 已排期),不是构念该合。

## 使用口径

- 这层划分是**展示与组织层**,不进入测量模型:权重、facet 结构、聚合规则仍以 `data/mapping_measurement_model_v3.json` 为准,不因大类归属改变。
- 与 RE_BENCHMARK_V1 的 C1–C5 主测分类是两套东西:C1–C5 按测试组织划分,本表按能力构念划分,不要混用。
- 报告展示建议:先给两大类的汇总画像(基础能力过不过门槛、教育能力强不强),再展开到 8 个子类,最后到 19 项原子能力。基础能力弱是通用短板,教育能力弱才是教育产品选型的核心信号——对应 README 的口径"通识 benchmark 是门槛项,不证明教学能力"。
