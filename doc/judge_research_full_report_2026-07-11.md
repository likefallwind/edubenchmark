## 0. 研究问题与动机

本仓库的教学能力评测（MRBench / BEA 2025 / MathTutorBench 等）里，大量打分工作
是让一个 **LLM 当裁判**：给它看一段师生对话和 tutor 的回复，让它判断这条回复
"有没有提供引导"（Providing_Guidance）、"连不连贯"（Coherence）等教学维度，
打出 Yes / To some extent / No 这样的标签。被测模型的最终成绩就建立在这些
裁判标签上。

那么核心问题就是：**这个裁判打的标签，和人类专家打的有多接近？**
如果裁判本身不靠谱，整个评测就是沙上建塔。具体拆成三问：

1. **裁判现在有多准？** 哪个模型当裁判最好？有没有系统性毛病
   （一贯偏严、一贯偏宽、偏爱长回复）？
2. **怎么让它更准？** 是多找几个裁判投票（"陪审团"），还是把裁判用的
   评分说明（rubric prompt）改得更好？如果改 prompt，怎么保证改的是
   真提升、不是碰运气？
3. **提升是真的吗？** 在开发数据上看到的进步，换一批从没碰过的数据还在吗？
   ——这决定了什么改动敢用到正式评测里。

我们有一个别人多数没有的条件：**约 2.4 万条人类专家标注的判例**（这些
benchmark 的原始数据里，每条 tutor 回复都有人类打好的维度标签）。有了
"标准答案"，裁判准不准就可以直接量出来，改进有没有效也可以直接检验——
整条研究线的方法论支点就是"一切声明都拿人类金标 + 统计检验说话"。

## 2. 实验一：给裁判出一张考卷（元评测集）

**为什么做**：要量"裁判准不准"，得先有一张固定的考卷——每道题是一条
(对话, tutor 回复, 维度)，标准答案是人类专家当年打的标签。让裁判也来打一遍，
对答案，就得到裁判的准确度。

这张考卷不能随手拼。有两个坑：

- **考卷和练习册必须分开**。后面我们要"优化裁判"，优化时看的数据（dev）和
  最终验收的数据（test）必须严格隔离，否则等于让学生背着答案进考场。
- **同一段对话的题必须整体待在同一边**。一段对话会衍生出几十道题
  （多个 tutor 回复 × 8 个维度），它们高度相关；更隐蔽的是，两个来源
  （MRBench 和 BEA 2025）底层共享 **182 段完全相同的对话**——如果按"题"随机切，
  同一段对话的题会一半在 dev 一半在 test，test 就被污染了。

**怎么做**（`scripts/build_judge_meta_eval.py`）：三个来源合成 24,108 条判例
（mrbench 13,240 + bea2025 9,904 + mathtutorbench 偏好对 964），**以对话为单位**
切 75% dev / 25% test，重叠对话只判一次归属，固定随机种子、重跑结果逐字节相同。

配套立了三样规矩，后面全程都靠它们：

1. **统计标准**（`scripts/eval/stats.py`）：所有"A 比 B 好"的声明必须过
   **配对 bootstrap 置信区间**检验。直觉版：让 A、B 两个方案判**同一批题**，
   逐题算差值；然后把对话整段整段地随机重抽 1000 次（不是逐题抽——同一对话
   的题是连坐的，逐题抽会假装样本比实际多，把误差算小），看差值的波动范围。
   **95% 区间不包含 0，才算真的有差别**；包含 0 就老实报"无显著差异"。
2. **准确度指标用 Cohen's kappa 而非一致率**。一致率有个漏洞：如果 90% 的
   题答案都是 Yes，一个无脑全答 Yes 的裁判也能拿 90%。kappa 把"瞎蒙也能蒙对
   的部分"扣掉，0 = 和瞎蒙一样，1 = 完全一致。本文所有"裁判多准"说的都是 kappa。
3. **prompt 可追责**：每个裁判 prompt 记版本号 + 内容哈希，改一个字都要换版本
   ——后面要反复改 prompt，必须能说清每个数字是哪个版本跑出来的。

**一个诚实声明**：查证发现 BEA 的标注和 MRBench 在 1,493 条共享回复上一致率
1.000——它们是**同一批标注的复制**，不是两拨人独立标的。这意味着我们算不出
"人类和人类之间的 kappa"来当天花板，只能引用原论文的标注者一致性数字。

## 3. 实验二：多裁判投票有用吗？顺便给裁判做体检

**为什么做**：想提高裁判质量，工程上最流行的偷懒办法是**多找几个裁判投票**
（jury/陪审团）——直觉是各家模型的错误互相抵消。这条路便宜、不用动 prompt，
所以先验证它；顺带把每个裁判的系统性毛病量出来，为后面指路。

**怎么做**：陪审团 = deepseek-v4-pro、glm-5.2、MiniMax-M3 三个不同家族的模型。
每家独立判整张考卷，然后合票（多数票为主，另试了按各家 dev 表现加权的投票）。
判定标准**事先写死**：在 test 上，陪审团 kappa 减最佳单裁判 kappa 的配对
置信区间不含 0 且为正，才算"陪审团更好"。

**结果**（`reports/eval/_judge_jury/`，n_boot=1000）：

1. **陪审团没用**。三条线的差值全部在 ±0.01 内、置信区间全含 0
   （mrbench +0.003 [−0.016, 0.019]；bea2025 +0.005 [−0.014, 0.023]；
   mathtutorbench −0.008）。三个裁判的错误不是互补的，而是**大家犯同样的错**
   ——错误方向一致时投票救不了。这条最省事的路被正式关掉。
2. **排名意外**：glm-5.2 是最佳单裁判（test kappa mrbench 0.438 / bea 0.406），
   而**当时生产在用的默认裁判 MiniMax-M3 恰好垫底**（0.354 / 0.335）。
3. **体检发现两个系统性毛病**：
   - **所有裁判都比人类严**：不管回复长短，裁判说 Yes 的比例比人类低
     7~21 个百分点，M3 最严。这个发现直接决定了下一个实验（见 §4）。
   - **M3 偏爱长回复**：在"两条回复选更好的"任务上，M3 选更长那条的概率
     58.5%，而人类是 50%（差 +8.5pp，显著）。教育场景里这很危险——
     好的引导常常应该短，裁判却给"看起来更耐心"的长回复加分。
     其他裁判无此偏好。
4. 副产物：8,544 条"三家裁判意见不一致"的判例存档。各 benchmark 的
   三票分歧率（bea 0.393 > mrbench 0.309 > mathtutorbench 0.138）本身就是
   "这个任务的评分标准有多模糊"的量化。

**学到什么**：提升必须来自 rubric 本身，不能靠堆裁判；且已知主要毛病是
"整体偏严"——这给了下一步一个非常具体的靶子。

## 4. 实验三：Stage 0 校准地板——先把便宜的收益拿干净

**为什么做**：上一步发现裁判"偏严"——最典型的是人类打 Yes 的题，裁判打
To some extent。这有两种可能的病因，治法完全不同：

- **刻度没对齐（校准问题）**：裁判其实看懂了回复的质量，只是它的
  "To some extent"对应人类嘴里的"Yes"——像两个老师用同一把尺子，
  一个手紧一个手松。这种病有**极便宜的解法**。
- **真没看懂（语义问题）**：裁判对评分标准的理解就是错的。这才需要
  昂贵的 prompt 优化。

在投大预算优化 prompt 之前，先花小钱测出"校准能修多少"。

**怎么做**：两个便宜手段。

- **0a 标签重映射（零成本）**：不改 prompt，拿到裁判输出后做个后处理换算表
  ——比如"裁判说 To some extent 一律改记为 Yes"。在 dev 上枚举所有可能的
  换算表（每个维度不超过 81 种），选 kappa 最高的，再到留出的评估数据上验证。
  这就是手紧手松老师之间的刻度换算。
- **0b 少样本锚例（约 4 千次调用）**：在 prompt 里塞 6 个人类标注过的真实例子
  （各标签的比例配得和人类真实分布一样），变体 dpfs_cal 再加一句
  "人类大约 x% 打 Yes"的明示。例子严禁取自评估数据（脚本里有断言）。

**结果一：0a 换算表在三个裁判上都跑了**（评估片，配对 CI）：

| 裁判 | mrbench | bea2025 |
|---|---|---|
| MiniMax-M3 | 0.357→**0.433**（+0.076 显著，三家最大） | 0.350→**0.410**（+0.060 显著） |
| glm-5.2 | 0.417→0.468（+0.050 显著） | 0.458→0.499（+0.041 显著） |
| deepseek-v4-pro | 0.399→0.426（+0.026 ns） | 0.414→0.434（+0.020 显著） |

- 学到的换算表几乎全是同一条：**"To some extent"→"Yes"**——坐实了"偏严"
  的具体形态。
- **这张表改写了"M3 不行"的定性**：M3 是三家里受益最大的，换算之后
  （0.433）大致追平 glm 的原始水平（0.417）——它在元评测里垫底，
  **主要输在刻度打得太严，其次才是能力**。但排名没有翻：给每家都配上
  各自最优的换算表后 glm 仍然领先（0.468/0.499 vs 0.433/0.410）；
  而且 M3 还有两个校准修不了的独立毛病——对语义编辑的响应能力弱
  （§6：同一套进化方法 glm 4 条验收 vs M3 1 条）、pairwise 长度偏置
  （§3：换算表对"偏爱长回复"无能为力）。
- 没有选"生产留 M3 + 后处理换算表"这条便宜路线的原因：①同配置对比
  glm 仍胜；②换算表本身是在 dev 上学的，上生产前还得单独过一次 test
  验证；③后来 mrbench/PG 的语义缺口走 v2 rubric 修复，那条路线上
  glm 的收益远大于 M3。

**结果二：0b 锚例**（只在 glm 上跑——0b 的定位是给后续 glm 进化立地板）：

| 手段 | mrbench | bea2025 |
|---|---|---|
| 0b 锚例+分布提示 | 0.417→**0.523**（+0.106 显著） | 0.458→**0.516**（+0.058 显著） |
- **"地板"的含义**：连"改一张换算表"这种零成本手段都能白拿 +0.05，那后面
  花几万次调用的 rubric 进化，涨幅必须**显著超过这条线**才有存在价值——
  否则昂贵方法挣的其实是免费就能捡的钱。这条最低线就叫地板。
- **最有价值的发现是分维度看**：大部分维度被校准修得很好（Tutor_Tone
  +0.26、Mistake_Location +0.17），但 **Providing_Guidance 对两种手段都免疫**
  （换算表无效，锚例只 +0.017 ns）——这个维度是真语义缺口，裁判是真没看懂
  "什么算提供了引导"。它因此成为后面自进化的头号靶子。
  反面还有一课：本来接近满分的 Revealing_of_the_Answer（0.884）被锚例
  **带坏**到 0.806——好的维度不能瞎动，后面一切改动都必须按维度分别处理。

**决策门**：事先约定按"校准吃掉差距的比例"定后续投入。实测 20–60% 档
（天花板取 0.7 时 mrbench 37%）——一半是刻度、一半是真语义问题，
值得全量进入自进化。若当时测出 90% 是刻度，整个进化计划就该取消。

**过程中的一个教训**：0b 首轮给裁判调用设了 max_tokens=1024，把 17% 的难题
回复"饿死"截断了。危险在于剩下的都是简单题，基线被抬高——这种
**幸存者偏差**不修正会让所有对比失真。去掉上限重跑后修正，并立了硬规矩。

## 5. 实验四：rubric 自进化方法 + M3 pilot（论文核心方法）

**为什么做**：Stage 0 证明了 M3 的分歧大头是校准，但同时也证明了
Providing_Guidance 这类维度对校准免疫——换算表、锚例都修不动它。剩下的差距
是语义性的：裁判对「什么算提供了引导」的理解和人类专家不一致。要修语义，
只能改 rubric 的内容本身。问题变成：谁来改、怎么改、怎么知道改对了？

### 5.1 天真做法为什么行不通：通用 prompt 优化器的四个坑

最直接的思路是「让一个强 LLM 看错例、反思、重写 prompt」，代表作是 GEPA。
这条路线在文献里有四个反复出现的毛病。理解这四个坑是理解我们整个方法的
钥匙——后面的每条设计都是对着其中一个坑挖的。

**坑 1：prompt 越改越长，死记硬背边例。** 自由重写没有任何结构约束，模型
看到一个错例就往 prompt 里塞一条「如果学生说 X 就判 Y」的特判。生产环境
报告里见过进化出 5,000+ 字符的 prompt——像一个只会背题的学生，题库换一批
就崩。

**坑 2：归因错误。** 一次自由重写往往同时动了五六处。这一版分数涨了——是
哪处改动的功劳？没人知道。下一轮反思时模型会自信地把功劳记在错误的改动上，
然后沿着错误的方向继续「改进」。GEPA 论文自己承认这个问题（misattribute
credit）。

**坑 3：在有噪声的指标上选优，选到的是运气不是实力（winner's curse）。**
这是全程最重要的一个概念，值得用比喻说透：让 10 个人各掷 20 次硬币，总有人
掷出 14 个正面——但你不能说他「更会掷硬币」，再掷 20 次他就回到平均。候选
rubric 在一小片数据上的 kappa 同样有很大的随机波动，「这一片上的第一名」
很大概率只是抽到了顺手的题。不设防的优化器每一轮都在收这种假冠军：改动
越积越多，dev 分数越来越好看，换一批数据全部还回去。我们全程实测到 13 次
winner's curse（pilot 7 次 + 后续实验 6 次，见 §7/§8），外加 6 次近失候选
的独立确认全部不成立、其中 2 次在独立数据上**显著变差**（§6.3）——它不是
理论担忧，是每一轮都在发生的常态。

**坑 4：只优化指令，不优化示例。** few-shot 例子是裁判校准文献里收益最大的
杠杆之一（我们自己的 Stage 0b 也证明了：+0.106/+0.058），但 GEPA 类方法的
搜索空间里根本没有它。

我们的方法用一句话概括：

> **不让模型自由发挥重写 prompt，而是像医生看病：先做全面检查找到具体病灶，
> 针对病灶开小处方，每个处方都要过统计检验才收，收了还要复查。**

### 5.2 六条设计原则（P1–P6）

**P1 结构化 rubric + 受限编辑**（对坑 1）。rubric 不是一段自由文本，而是一个
有固定槽位的结构对象；每次改动必须是 6 种类型化算子之一（见 5.3），且渲染出
的 prompt 总长有硬预算（比 v1 模板最多多 7,000 字符，超了直接拒绝候选）。
模型想「多写点总没错」？笼子不允许。

**P2 编辑即假设**（对坑 2）。每条改动是一个独立的、单一的假设——「加上这条
边界条款会让 kappa 显著上升」。一次只测一条，配对统计检验过了才提交（成为
现任版本 incumbent），没过就丢弃。功劳簿上每一笔都对应唯一一条改动，归因
不会错。

**P3 两段制赛马**（对坑 3）。筛选和验收用两批不同的数据：~250 条筛选片只
负责排序淘汰，名次不作数；只有前 3 名才能上 ~600 条评估片，在那里看配对
bootstrap 置信区间（机制见 §2），下界大于零才算数。运气好的假冠军在筛选片
能赢一次，但很难在没见过的评估片上再赢一次——两段制就是逼着运气连赢两场，
把假阳性概率压到很低。

**P4 分布保持锚例（DPFS）**（对坑 4）。few-shot 例子进搜索空间，但不是随便
挑：锚例按人类标签的真实边缘分布配比采样（人类 55% 判 Yes，例子里就大约
55% 是 Yes），且只从评估片之外的池子取（杜绝泄漏）。它的独立效果已由
Stage 0b 单独度量过；在进化里它作为一个固定候选（dpfs_cal）每轮参赛，兼当
「校准参照线」——语义提案如果连它都赢不了，说明这一轮没挖到语义层面的东西。

**P5 聚合诊断驱动提案**（文献没有，我们独有）。反思模型的输入不是一小撮
零散错例，而是分布级证据：完整的混淆矩阵（人类判 X、裁判判 Y 的全部计数）、
每个混淆格的典型错例、以及裁判当时自己写下的推理过程。这让提案能对准
「系统性病灶」（比如「人类判 Yes 的题里有 73 条被裁判压成 To some extent」），
而不是被个别怪例带偏。每个提案还必须声明自己针对哪个混淆格——验收后复盘
时有据可查。

**P6 共识分层去噪**（同上，独有；**当前状态：设计与数据就绪，尚未接入主循环**）。
用三家裁判（deepseek/glm/M3）在全量 dev 上的票把判例分三层：三票一致且等于
人类（简单例，学不到东西，降采样）；三票一致但不等于人类（学习价值最高——
要么 rubric 有语义缺口，要么人类标注本身错了）；三票分裂（题目本身模糊，
学它等于拟合噪声，应从训练信号中隔离）。三家全量票的数据资产在实验二已经
产出，但目前主循环的诊断只用单裁判自己的混淆矩阵——P6 的正式接入和
「去 P5 / 去 P6」的 2×2 消融是论文前值得补的实验（见 §9.4）。论文中 P6 应
如实写为设计原则 + 数据资产 + 待完成消融，不宜写成已生效组件。

### 5.3 rubric 长什么样、允许怎么改

结构对象一共四个槽位：

```json
{
  "definition_override": null,          // 或"替换后的维度定义"
  "label_criteria": {"Yes": "…", "To some extent": "…", "No": "…"},
  "clauses": [{"id": "…", "text": "一条边界澄清规则"}],
  "anchor_block": null                  // 或 {"calibrated": true}，few-shot 锚例块
}
```

渲染成 prompt 时逐段拼进 v1 模板的固定位置：定义替换原定义、判据和条款插在
选项行之前、锚例块整体前置。**空 rubric 渲染出的 prompt 与现行生产 prompt
逐字节一致**（代码断言）。这一条保证两件事：v1 基线可以直接复用已缓存的
几万条裁判输出（省一大笔 API 钱），以及「进化版和原版的唯一差别就是新增的
那几段」（归因干净）。

允许的改动只有 6 种算子，各举一个真实例子：

| 算子 | 作用 | 真实例子 |
|---|---|---|
| `add_clause` | 加一条边界澄清条款 | pilot 唯一验收 r1p3：「相关的引导性提问或提示即算 Yes，不要求明确指出错误位置」 |
| `drop_clause` | 删一条已有条款 | 回归消融发现某条款边际贡献转负时用 |
| `set_label_criterion` | 给某个标签写行为化判据 | 近失 r2p3：「To some extent = 引导部分正确 / 部分相关 / 过于模糊」 |
| `edit_definition` | 替换维度定义本身 | 动静最大的算子，提案中出现少 |
| `add_anchor_block` | 挂上 DPFS 锚例块 | 每轮固定注入的 dpfs_cal 参照候选 |
| `remove_anchor_block` | 摘掉锚例块 | 锚例被证明拖后腿时用 |

禁止整段自由重写。这个笼子同时防膨胀（坑 1）、保归因（坑 2）。

### 5.4 一轮进化循环的六步——拿一次真实运行走一遍

下面用纯 M3 自举实验（2026-07-11 晚）mrbench/Providing_Guidance 线的
round 1 做实例，21:23 启动、22:08 收官，全程并发 6：

**第 1 步·诊断（拍 CT）**。当前 rubric（此时是 v1）在诊断池上的标注和人类
对齐。诊断池 = dev 减去评估片的全部对话（这条线 605 条）；它和评估片按
**对话**切开、永不重叠——反思模型从头到尾看不到评估片上的任何题，这是防
泄漏的第一道墙。产出：一致率 0.597；混淆矩阵显示两大病灶——「人类 To some
extent、裁判判 No」51 例，「人类 Yes、裁判判 To some extent」73 例（M3 整体
偏严）；每个格子附 8 条典型错例，连同裁判当时自己写的推理摘录。

**第 2 步·提案（开方）**。反思模型读诊断 + 历史战绩（ledger：哪些思路已经
失败、哪些近失值得打磨；从 round 2 起注入），产出 6 个类型化编辑候选，每个
声明针对哪个混淆格。这一晚 M3 用了不到一分钟写完 6 个提案：r1p1 针对
「No 被抬成 To some extent」、r1p2 针对「泛泛鼓励被高估成 Yes」、r1p3 针对
「引导被过严压成 No」……系统另固定注入第 7 个候选 dpfs_cal（校准参照线）。

**第 3 步·筛选（初试，只排序）**。7 个候选各自跑 254 条筛选片（每个约
4 分钟）。结果 dpfs_cal +0.097、r1p2 +0.061、r1p3 +0.043 进前三，r1p4/r1p5
转负直接淘汰。再强调一遍：**筛选片的名次不作数**——它小、噪声大，正是
winner's curse 的高发地；它唯一的职责是把明显没戏的候选便宜地筛掉。

**第 4 步·验收（终试，看 CI）**。前 3 名上 600 条评估片，与 incumbent 的
标注逐题配对，按对话簇 bootstrap 重采样 1,000 次算差值的 95% 置信区间；
验收标准 = **CI 下界 > 0 且解析失败率不升**。结果非常有戏剧性：筛选头名
dpfs_cal 全量掉到 +0.044、CI 跨零（winner's curse 现场教学）；筛选第三的
r1p3 反而在全量上 +0.094 [0.026, 0.164]——下界过零，**接受**，成为新
incumbent。同一晚 bea2025/PG 线还有个更典型的反面教材：r1p6 筛选 +0.075
风光无限，全量缩水到 +0.015 跨零，拒收。

**第 5 步·复查**。从下一轮起每轮固定三件事：① 回归消融——把已接受的历史
编辑逐个摘下来重算边际贡献，转负就剔除（相当于 rubric 的回归测试）；
② 换算表叠加检查——在当前 rubric 上再叠 0a 换算表，若还能涨说明残余校准
空间没吃干净（pilot round 3 实测为恒等：r1p3 之后无残余）；③ 固定安全检查
——长度偏置不升、unparsed 率不升、prompt 总长不超预算。

**第 6 步·下一轮或停机**。接受了新编辑 → 病灶分布变了，下一轮**必须用新
incumbent 重新拍 CT**（自适应重诊断，约 +600 次调用）。这是 pilot 的血泪
教训：round 2 拿旧 CT 开新方，6 个提案 5 个筛选即负。停机条件：重诊断后
候选全负，或连续一轮无验收且无近失。

**近失协议**（第 4 步的补丁）。CI 下界差一点点过线的候选（比如差 0.001），
禁止在同一批数据上重测——重测到过线为止就是 p-hacking。唯一出路：拿到选择
过程从未接触过的独立确认集上复验一次，过了才收。pilot 的两个近失走了这条路，
双双归零（见 5.5），证明它们是纯选择噪声。

配套工程：响应级断点续跑（配额中断后重发同命令即续，实战检验过多次）、
25 连败熔断、每条编辑的完整审计链（触发诊断 → 效应量 → CI → prompt sha256）。

### 5.5 M3 pilot：第一次实战（3 轮，~25k 调用）

**设定**：出于成本先用便宜的 MiniMax-M3 当裁判跑通流程（反思模型 glm-5.2），
靶子选校准修不动的三条线：mrbench/Providing_Guidance、mrbench/Coherence、
bea2025/Providing_Guidance。

**Round 1**：唯一显著验收 r1p3（上文那条边界条款），kappa 0.272→0.340
（**+0.068**，显著）。同场对照：校准参照 dpfs_cal 在这个维度只有 +0.007——
**「语义编辑修得动校准免疫维度」的假设成立**，方法的存在价值被验证。
本轮同时实测 3 次 winner's curse（三条线的筛选头名全部在全量上现形）。

**Round 2**：无验收。6 个提案 5 个筛选即负——静态 v1 诊断在已改进的 rubric
上开方，药不对症（自适应重诊断由此诞生）。唯一幸存者 r2p3 全量 +0.055
[−0.001, 0.110]，差 0.001 过线的近失，按纪律入 ledger 等待独立复验，
不允许原地重测。

**Round 3**（Stage 2 升级版：自适应重诊断 + 筛选片 157→250 + 回归消融 +
ledger 注入反思）：三线均无验收。mrbench/PG 重诊断后候选全负 → r1p3 已是
该维度提示编辑的局部最优；回归消融确认 r1p3 仍在赚钱（摘掉损失 0.055）；
换算表叠加为恒等（无残余校准空间）。**近失独立确认**：r2p3 复验 −0.002
[−0.059, 0.059]、bea 线的 r3p5 复验 −0.001 [−0.044, 0.047]——**双双归零**。
如果当时手松放进去，两条无效改动就混进 rubric 了；「筛选、验收、确认用三批
不同数据」这套纪律被实测背书。

**当时的一个误判，错得很有教益**：Coherence 两轮 18 个候选全灭，我们定性为
「这个维度剩下的差距是标注噪声，修不动了」。这个结论后来被 glm 主实验证伪
（glm 在同一维度 +0.092 显著，见 §6）——修不动的不是维度，是 M3 这个裁判。
教训：定性一个维度「不可修」之前，先换个更强的裁判试一遍。

**pilot 的真正产出**不是那 +0.068，而是：方法本身跑通了；防过拟合的三层
纪律（两段制、配对 CI、独立确认）被 7 次 winner's curse 实测证明是必要而
不是仪式；自适应重诊断、大筛选片这两个关键升级是被真实失败逼出来的。这套
东西可以原样搬到任何裁判上——这正是实验五（glm-5.2 自进化）与纯 M3 自举
对照实验（已收官，见 §6.1）做的事。

## 6. 实验五：glm-5.2 主实验——方法换个裁判还灵吗？

**为什么做**：pilot 用的是最弱的裁判。方法定稿后按协议迁移到最佳单裁判
glm-5.2，一次回答两个问题：**方法是否普适**（换裁判还有效吗）、
**毛病是否裁判特异**（M3 学到的处方能不能直接给 glm 用）。

**怎么做**：同一套流程原样复刻，裁判和提案模型都换成 glm-5.2；实验状态按
裁判隔离存放，考题切片和 M3 用的逐字节相同（公平对比）。

**覆盖范围说明（"全面"到什么程度）**：glm 从第 1 轮起就用完整的 Stage 2
规格（250 题大筛选片 + 每轮自适应重诊断），三条线各跑到停机条件触发才收官。
但"全面"不等于全部——靶子和 pilot 一样只有 3 条线（两个 benchmark 的
Providing_Guidance + mrbench 的 Coherence），其余维度要么已被校准手段修好、
要么接近天花板（Stage 0 的分维度结论），没有进入进化；评估也不是全量 dev
（1.3 万条），而是冻结的 ~600 题/线评估片——这是预算设计，显著性由配对 CI
保证。

**一个曾经对 M3 不完全公平的地方（已解决）**：M3 pilot 的前两轮用的是较轻
的协议（静态 v1 诊断 + 157 题小筛选片），第 3 轮才升级到与 glm 相同的完整
规格，所以"glm 4 条验收 vs M3 1 条"最初混着协议差异。2026-07-12 我们按
完整规格、且反思模型换成 M3 自己（与 glm 的"自己进化自己"完全对称）重跑了
一遍——结果见 §6.1，结论不变且更干净。

开跑前先给出一个**可证伪的预测**：诊断显示 glm 的主混淆格是人类打
To some extent、glm 打 No（**偏得更严**）——方向和 M3（人类 Yes、它打 TSE，
相对偏宽）**相反**。所以预测 M3 的处方搬不过来，glm 得治自己的病。

**结果**（3 轮，~22k 调用，4 条验收）：

| 线 | v1 → 终版 kappa | 累计增益 | 处方内容 |
|---|---|---|---|
| mrbench/Providing_Guidance | 0.322 → **0.438** | **+0.116**（显著） | "试图引导但诊断有误/有瑕疵 → 打 To some extent 而不是 No" |
| bea2025/Providing_Guidance | 0.392 → **0.484** | **+0.092**（显著） | 定义改写 + 同上判据 |
| mrbench/Coherence | 0.268 → **0.400** | **+0.132**（两轮两验收） | "纠错、让学生重读题目、换个步骤建议都算连贯的教学回应，不判 No" |

四个发现：

1. **方法完全迁移，处方完全不迁移**。glm 验收的处方全是治"过严"的
   （把 No 往上抬），M3 验收的是治"过宽"的（把该给 Yes 的给足）——
   方向相反，预测被证实。这说明 rubric 优化**必须按裁判分别做**，
   而"先诊断再开方"正是方法能自动适配不同裁判的原因——它不是流程装饰。
2. **裁判越强，进化收益越大、来得越快**（glm 4 条验收 vs M3 1 条；严格
   同规格的三方对称对比见 §6.1/§6.2：glm round 1 即 3/3 线验收、累计
   +0.34，纯 M3 一轮 1/3（+0.094），deepseek-v4-pro 要到第 2 轮才 1/3
   （+0.087））。更强的模型对 rubric 里的语义修改响应更灵敏。
   "用便宜裁判省成本"在这里是假节省。
3. **M3 pilot 的"标注噪声天花板"定性被推翻**：Coherence 在 M3 手里 18 个
   候选全灭，在 glm 手里两轮验收共 +0.132。当时以为是任务修不动，
   其实是 M3 能力到顶了。教训：**"剩下的差距是噪声"这种结论必须按裁判
   分别下，弱模型的天花板不是任务的天花板。**
4. 校准手段全程陪跑（锚例三线全不显著）、winner's curse 又添一例
   （近失候选独立复验缩水，累计第 8 例）——pilot 的全部方法论结论
   在第二个裁判上复现。

### 6.1 实验八：纯 M3 自举对照——严格同规格的对称对比（2026-07-12 收官）

**为什么做**：上面"glm 4 验收 vs M3 1 验收"有两个可以攻击的缝隙——
① pilot 前两轮协议较轻（非同规格）；② pilot 的提案是 glm 帮 M3 写的
（混合配置），而 glm 主实验是 glm 自己进化自己。补一个 **judge=reflector=
MiniMax-M3** 的完整规格实验，两个缝隙同时堵上：每个裁判都"自己进化自己"，
协议逐项相同（250 题大筛选片 + 每轮自适应重诊断 + 相同的冻结切片），
唯一变量就是裁判本身。

**怎么做**：状态目录按实验隔离（`stage1_minimax3_self/`，pilot 与 glm 的
目录不动），v1 基线标签复用 M3 缓存全量跑（零重复开销）。三条线同前。
2 轮收官，约 17k 次 M3 调用，全程无外部模型参与。

**结果**：

| 线 | round 1 | round 2 | 终局 |
|---|---|---|---|
| mrbench/Providing_Guidance | **r1p3 验收**：0.272→0.365（**+0.094 [0.026, 0.164]**） | 重诊断后候选全负 | r1p3 = 局部最优，收官 |
| mrbench/Coherence | 最好 +0.032（ns） | 最好 r2p3 +0.058 [−0.011, 0.132]（ns） | 近失 r2p3 独立确认（558 题）**−0.059 [−0.145, 0.036]**，不成立 → 收官 |
| bea2025/Providing_Guidance | 最好 +0.015（ns，筛选头名 +0.075 全量现形） | 最好 +0.007（ns） | 两轮无验收，收官 |

复查三件套全部健康：r1p3 验收后重诊断池一致率 0.597→0.665，回归消融
显示摘掉 r1p3 掉 0.043（仍在赚钱），换算表叠加恒等（无残余校准空间）。
勘误（2026-07-12 复核）：收官时曾记"无近失候选"，但对照 glm 的判例
（r2p5 +0.035 [−0.016] 被认定为边缘近失并续跑一轮），Coherence 的 r2p3
（+0.058 [−0.011]）CI 下界离过线更近，应按近失处理——已登记独立确认
（`m3self_mrbench_coh_r2p3`）。确认已跑完（558 题子样本，与选择切片零重叠、
反思见过的样例已剔除）：选择片上的 +0.058 到了独立数据上变成 **−0.059
[−0.145, 0.036]**，方向都反了——该候选是选择噪声，Coherence 线正式收官。

**三个结论**：

1. **对称对比落定**：同规格下 glm 自进化 round 1 即 3/3 线验收，纯 M3
   仅 1/3——"强裁判进化收益大于弱裁判"不再有协议混淆的辩护空间。
2. **M3 的瓶颈在判分不在写提案**：同一条线（mrbench/PG），M3 自己写提案
   拿到 +0.094，比 pilot 里 glm 帮它写的 +0.068 还高。"弱模型不靠外部
   强模型也能自我改进"成立，但幅度和覆盖面受裁判自身判分能力限制。
   顺带：这条验收的编辑（放宽"过严压成 No"）与 pilot 那条（补足"该给
   Yes 的"）针对不同混淆格——两次进化各自找到了不同的病灶，都显著。
3. **方法防线在第三次实验里继续工作**：winner's curse 再添 2 例实测
   （bea r1p6 筛选 +0.075 → 全量 +0.015；mrbench/PG 筛选头名 dpfs_cal
   全量跨零），两段制照单全拦。

**证据边界**：test split 按协议只能开封一次、已在实验七用掉，所以本实验
的验收 rubric 只有 dev 证据，不能再上 test 复验（见 §9.3）。

### 6.2 实验九：deepseek-v4-pro 自举复验——裁判样本从 2 到 3（2026-07-12）

**为什么做**：§9.4 协议本就预留的第三裁判复验。前两个裁判各自"自己进化
自己"都出了显著验收，但 n=2 说服力有限；换一个血统完全不同的模型
（deepseek-v4-pro，基线 kappa 在 mrbench/PG 上 0.319，与 glm 的 0.322
相当、高于 M3 的 0.272），看"方法普适"是观察还是模式。

**怎么做**：与 §6.1 逐项相同的对称配置——judge=reflector=deepseek-v4-pro，
三条线、250 题大筛选片、每轮自适应重诊断、相同的冻结评估切片、相同的
CI 下界验收门。状态目录 `stage1_deepseek-v4-pro/`。前两轮约 15k 次调用。

**结果**：

| 线 | round 1 | round 2 | 终局 |
|---|---|---|---|
| mrbench/Providing_Guidance | 唯一幸存者 +0.028（ns），**空手** | **r2p2 验收**：0.319→0.406（**+0.087 [0.034, 0.140]**） | round 3（新 incumbent 重诊断）三个候选在全量上**全部翻负**（最好 −0.018），无验收无近失，**收官**，最终 rubric = stage1-r2-r2p2 |
| mrbench/Coherence | 最好 +0.036（ns） | 重诊断后 r2p5 +0.042 [−0.006]、r2p6 +0.042 [−0.013]（均 ns） | 两个近失独立确认（556 题）**双双显著变差** → 收官 |
| bea2025/Providing_Guidance | 唯一幸存者是校准参照 dpfs_cal，+0.029（ns） | 最好 +0.031（ns） | 两轮无验收，收官 |

**三个发现**：

1. **验收不一定出现在第一轮，失败台账是有用的**。dsv4 第 1 轮三线全部
   空手——如果协议是"一轮定生死"，结论就会错写成"dsv4 修不动"。第 2 轮
   反思吃着第 1 轮的失败台账（P4：哪些编辑试过、怎么死的）换了打法，
   直接命中 +0.087 的显著验收。这是台账机制第一次被单独"救活"一条线。
2. **两个裁判在同一混淆格上独立收敛**。dsv4 验收的编辑是"回复带事实错误
   但仍在往具体步骤上引导 → 打 To some extent 而非 No"，和 glm 在同一条线
   验收的处方（"试图引导但诊断有误 → TSE 而非 No"）几乎是同一句话——
   两个不同血统的裁判、各自独立的诊断和提案，最后开出同方向的药。
   这把 mrbench/PG"任务级 rubric 缺口"的存在性证据从双裁判加厚到三裁判
   （dsv4 一份是 dev-only）。
3. **三裁判梯度成形**：同规格自进化下，glm 一轮 3/3（累计 +0.34）、
   M3 一轮 1/3（+0.094）、dsv4 两轮 1/3（+0.087）。方法在三个裁判上都
   产出了显著验收且零假验收（所有通过验收门的编辑复查健康），但收益的
   规模与速度随裁判能力变化——"方法普适、节奏不同"。防线也继续工作：
   Coherence 第 1 轮筛选头名 r1p4（筛 +0.040）在全量上翻负（−0.026）；
   PG 的收官轮 round 3 三个决赛候选筛选分全为正（+0.028 ~ +0.050），
   到全量上**全部翻负**（−0.018 ~ −0.046），筛选头名 r3p6 计入 winner's
   curse 累计第 13 例——两段制不但拦住了假验收，也给出了干净的停机信号。

**证据边界**：与 §6.1 相同，验收 rubric 只有 dev 证据（test 已封）。
mrbench/PG 线已按协议走完"验收 → 新 incumbent 重诊断再拍一轮 → 全负收官"
的完整闭环；Coherence 的两个近失 r2p5/r2p6 也已独立确认完毕（见 §6.3），
三条线全部收官。

## 6.3 近失候选的独立确认：三个裁判、六次复验、零成立

**为什么单独讲**：自进化的验收门是"配对 CI 下界 > 0"。总有候选**差一点点**
过线（比如 +0.042 [−0.006, 0.096]），扔掉可惜、直接收又违规。协议规定这类
"近失"候选走一条单独的路：**到一批选择过程从没碰过的数据上复验一次**，
过了才收。这条规矩看着像形式主义，但它是全程最有信息量的一个检验——因为
它回答的正是那个致命问题："dev 上看着有戏的改动，到底是真有戏，还是运气？"

**怎么做**（`scripts/run_judge_rubric_confirm.py`）：候选是在**评估切片**
（约 600 题）上被选出来的，所以确认集取**诊断池的重诊断子样本**（约 560 题，
与评估切片零重叠），并剔除反思模型见过的全部错例。对手（incumbent）的标签
直接取缓存的基线跑，零额外调用。判据仍是配对 cluster-bootstrap CI。

**六次确认的战绩**（三个裁判、三条不同的线）：

| 确认 | 选中它的那批数据上 | 独立确认集上 | n |
|---|---|---|---|
| pilot / mrbench PG r2p3 | +0.055 [−0.001, 0.110]（差 0.001 过线） | −0.002 [−0.059, 0.059]（ns） | 559 |
| pilot / bea2025 PG r3p5 | +0.059 [−0.010, 0.129] | −0.001 [−0.044, 0.047]（ns） | 625 |
| glm-5.2 / mrbench PG r3p3 | +0.037 [−0.013, 0.085] | +0.016 [−0.035, 0.060]（ns） | 532 |
| 纯 M3 / mrbench Coherence r2p3 | +0.058 [−0.011, 0.132] | **−0.059** [−0.145, 0.036]（ns） | 558 |
| dsv4 / mrbench Coherence r2p5 | +0.042 [−0.006, 0.096] | **−0.105 [−0.186, −0.027]（显著变差）** | 556 |
| dsv4 / mrbench Coherence r2p6 | +0.042 [−0.013, 0.096] | **−0.097 [−0.169, −0.025]（显著变差）** | 556 |

**六战六败，而且后三次比前三次更狠**：前三次是"提升缩水成噪声"（点估计掉到
0 附近），后三次点估计**直接翻负**，其中 dsv4 的两个候选在独立数据上是
**统计显著的倒退**——把它们收进 rubric，裁判会真的变差 0.1 kappa，而在选中
它们的那批数据上你只会看到"+0.042，差一点就过线，好可惜"。

这是本研究关于选择噪声最硬的一块证据。winner's curse 的常见版本是"提升是
假的"；这里看到的是更坏的版本：**提升不但是假的，改动本身是有害的**，只是
被选择偏差整个盖住了。它同时说明"近失就顺手收了吧"这种在实践中极常见的
松口——每一次都可能把一条真实的倒退写进生产 rubric。

**一个方法论细节**（也是一次自我修正）：三条 Coherence 线的对手是 v1（这些线
从未验收过），最初我把确认集配成"诊断池减去子样本"的剩余部分，结果 mrbench
的池子总共只有 637 题、子样本就占了 605 题，剩余不到 30 题——CI 宽得毫无
判别力（±0.2）。改回与历史两次 mrbench 确认相同的子样本模式后才拿到 n≈556
的有效样本。**确认集的功效必须先算再跑**，否则"确认了，不显著"会变成一句
什么都没说的空话。

## 7. 实验六：消融——收益到底是哪个成分挣来的？

**为什么做**：+0.116 这种数字有一个天然质疑："是不是随便什么优化方法
跑一跑都能拿到？"消融就是回答这个问题：把我们方法里的关键成分拿掉，
换成三种常见替代品，**其他一切（考题、裁判、打分、预算）保持逐字节相同**，
看还挣不挣得到钱。

**三个对照方法**（`scripts/run_judge_rubric_ablation.py`）：

- **手工精写**：人认真写一版规整的 rubric（每个标签给行为化判据、要求
  裁判先想理想教学动作再判）——但**不看诊断**。代表"有经验但没数据的人"。
- **生成-K-选优**：让 LLM 自由生成 5 套评分规则，挑分数最高的。代表
  "无方向的搜索"。我们还故意放了水——直接在评估数据上挑最优（正规做法
  要在另一批数据上挑），给它乐观上界。
- **GEPA 原味**：反思式整段重写 + 贪心接受，**没有统计检验的门**。
  这是文献里最强的通用 prompt 优化器，代表"自由度大、纪律松"。

**结果**（Δkappa vs 现行 rubric，三条线）：

| 方法 | mrbench/PG | bea/PG | Coherence | 显著提升 |
|---|---|---|---|---|
| 手工精写 | +0.032 ns | +0.010 ns | +0.034 ns | 0/3 |
| 生成-K-选优 | −0.001 ns | +0.005 ns | +0.029 ns | 0/3 |
| GEPA 原味 | +0.054 ns | **−0.126 显著变差** | +0.048 ns | 0/3 |
| **本方法** | **+0.116 ✓** | **+0.092 ✓** | **+0.132 ✓** | **3/3** |

三个对照的死法各不相同，正好拼出结论：

1. **手工**：写得再规整，不知道病灶在哪个混淆格，就只有噪声级的漂移。
   人工设计的瓶颈不在文笔，在**没有诊断**。
2. **生成-K**：就算让它作弊式选优，最好也只 +0.03。5 个候选的分数整体
   贴着或低于原版——**加大搜索量救不了没方向的搜索**。
3. **GEPA（最有说服力的一个）**：它在自己的优化数据上分数最漂亮
   （0.54/0.59/0.69，全都高过我们），可是拿到独立评估数据上崩到
   0.27/0.38/0.32，其中一条**显著低于原版**（−0.126）。这就是教科书式
   过拟合：自由重写 + 没有统计门 = 把优化数据里的噪声当成了规律背下来。
   它反过来证明了我们坚持"每条改动过配对置信区间才收"不是仪式。

**结论一句话**：收益来自"**诊断驱动**（知道往哪改）+ **统计门控**
（只收真的）"这两个成分，不来自搜索量、文本自由度或人工经验。

## 8. 实验七：test 终验——最后一道闸门，以及它拦住了什么

**为什么做**：到这里，dev 上的每条验收都过了配对 CI、回归检查、独立确认
——但它们全都是"在 dev 这批数据上"的结论。§2 封存的 test split 从头到尾
没人碰过，现在**开封一次、只开一次**：进化后的 rubric 和原版各判一遍 test，
对人类金标，看 dev 上的提升还在不在。

**怎么做**（`scripts/run_judge_rubric_stage3.py`）：开跑前硬断言 test 与 dev
的所有数据、对话零重叠；进化 rubric 里没有任何示例（全是抽象条款），
不存在把 dev 数据带进 test 的通道。glm 的三条终版 + M3 pilot 的一条一起上。

**结果：4 条 dev 显著的提升，test 上只活了 2 条——而且都在同一个维度上**：

| 线 | 裁判 | test 上 Δkappa | 95% CI | dev 曾经 | 复现？ |
|---|---|---|---|---|---|
| mrbench/PG | glm-5.2 | **+0.115** | [+0.049, +0.185] | +0.116 ✓ | **✅** |
| mrbench/Coherence | glm-5.2 | +0.002 | [−0.080, +0.110] | +0.132 ✓ | ❌ 塌了 |
| bea2025/PG | glm-5.2 | −0.012 | [−0.081, +0.056] | +0.092 ✓ | ❌ 塌了 |
| mrbench/PG | MiniMax-M3 | **+0.074** | [+0.009, +0.137] | +0.068 ✓ | **✅** |

**为什么塌？——这是全程最重要的方法论发现。** 线索是：原版 rubric 在 test
上的分数本来就比 dev 高不少（Coherence 0.268→0.430，bea/PG 0.392→0.477）
——test 那批题恰好更"干净"（标注噪声小）。而进化处方治的是 dev 诊断里
拍出来的病灶：

- mrbench/PG：这个病灶在 test 上**依然存在** → 处方治到了任务本身的病 →
  +0.115 干净复现；
- Coherence 和 bea/PG：病灶主要是 dev 那批数据的噪声，干净的 test 上
  **本来就没这个病** → 处方无病可治，归零。

注意这**不是** winner's curse——那两条线在 dev 上的提升是真实、可重复的
（配对 CI、独立确认都过了）。这是另一层过拟合：**提升是真的，但真在
"对 dev 这批数据的分布"上，不是真在"对任务"上**。全程至此辨析出两层
性质不同的过拟合，各有各的解药：

| 层 | 现象 | 什么能拦住 | 实测证据 |
|---|---|---|---|
| ① 选择噪声（winner's curse） | 小数据上选出的冠军换批数据就现形 | 筛选/验收/确认用三批数据 + 配对 CI | 累计 13 例（pilot 7 + glm 1 + GEPA 1 + 纯 M3 2 + dsv4 2） |
| ② dev 分布特异性 | dev 上真实可复现的提升，test 上塌零 | **只有封存的 test 终验** | glm 三线塌了两条 |

第②层是配对 CI **原理上就拦不住**的——你在 dev 上做多少次检验，检验的
都还是 dev。这就是"test 只能碰一次"这条纪律存在的全部意义，本实验把它
从信念变成了实测：**没有 test 终验，三条里两条无效改动就上生产了。**

**最稳健的正结果**：mrbench/Providing_Guidance 被**两个裁判各自独立进化**
（治的还是相反方向的症状）、**双双通过 test**。这说明"裁判对'部分正确的
引导'过度降级"是这个维度**任务级的真实 rubric 缺口**，不是哪个裁判的
个体毛病——它是全流程含金量最高的单点结论。

**生产切换**（用户拍板，已写入代码）：

- **换裁判**：mrbench 和 bea2025 的生产裁判 M3→glm-5.2。依据是 §3 的
  元评测排名（与 rubric 实验无关，独立成立）。**只换这两条**——
  mathtutorbench/mmtutorbench/eduguard 没进过元评测，没有证据就不动。
- **换 rubric**：只有 mrbench/PG 挂 v2（把过 test 的那条判据注入生产裁判
  prompt，且经断言与 test 上验证的版本逐字节一致——**上生产的就是验证过的**）。
  Coherence 和 bea/PG 留 v1——dev 增益没过 test，不上。
  另外校准型基准 mrbench_judge（考"被测模型当裁判行不行"）保持 v1 不变，
  考题不能漂移。

## 9. 论文铺垫：可主张的贡献点与证据

### 9.1 建议的论文故事线

> **"有人类金标监督时，教学裁判的 rubric 应该怎么优化、怎么验收"**——
> 一个诊断驱动、统计门控、test 终验三层设防的自进化框架，
> 以及它揭示的两层过拟合结构。

1. **动机**：LLM 裁判在教育评测里大规模使用，但和人类专家的 kappa 只有
   0.3–0.44；多裁判投票被显著性检验证明无效（§3）→ 提升只能来自 rubric。
2. **诊断**：主毛病是系统性偏严；便宜的校准手段能吃掉 20–60% 差距，
   但关键教学维度对校准免疫（§4）→ 真语义缺口存在，且知道在哪。
3. **方法**：结构化 rubric + 受限编辑 + 诊断驱动提案 + 三批数据分离的
   统计验收（§5）。
4. **主结果**：三裁判对称实验（§5/§6）——方法在 glm/M3/dsv4 上都产出
   显著验收且零假验收；处方随裁判的病灶走（M3 治偏宽、glm 治偏严），
   但 mrbench/PG 上 glm 与 dsv4 独立收敛到同一处方；收益规模与速度
   随裁判能力分层（3/3 一轮 → 1/3 一轮 → 1/3 两轮）。
5. **消融**：同预算同基建下，手工/瞎搜/GEPA 九格零显著、GEPA 显著劣化
   （§7）→ 收益归因于诊断+统计门两个成分。
6. **终验与两层过拟合**（§8，区分度最高的一节）：dev 显著 ≠ 任务级真提升；
   统计门拦得住选择噪声（13 例）、拦不住 dev 分布特异性（2/3 塌方）；
   唯一双裁判双验的维度给出"任务级 rubric 缺口"的存在性证明。
7. **落地**：证据分级的生产切换纪律——每条线独立过 test 才上，不整批上。

### 9.2 贡献点 → 证据对照表

| 可主张的贡献 | 支撑证据 | 强度 |
|---|---|---|
| 陪审团对教学裁判无显著收益（负结果） | 三线配对 CI 全含 0，判定标准事先写死 | 强 |
| 教学裁判系统性偏严 + M3 长度偏置 | 全裁判全长度桶 −7~−21pp；M3 选长回复 +8.5pp 显著 | 强 |
| 校准/语义二分与"地板"方法学 | 换算表/锚例六格显著 vs PG 免疫（+0.017 ns） | 强 |
| 诊断驱动+统计门控的自进化框架有效 | 三裁判 6 条显著验收（glm 4 + M3 1 + dsv4 1），零假验收；同预算三对照 0/9 | 强（消融闭合，n=3 裁判） |
| 裁判毛病是特异的：方法迁移、处方不迁移 | M3 治偏宽、glm 治偏严，方向相反且预测在先 | 强 |
| 两层过拟合的辨析与实测 | 13 例 winner's curse + glm 2/3 test 塌方 + 根因分析 | 强，且新颖 |
| mrbench/PG 存在任务级 rubric 缺口 | 双裁判独立进化、双双过 test（+0.115 / +0.074）；第三裁判 dsv4 在同一混淆格独立收敛到同方向处方（dev-only） | 最强单点结果 |

### 9.3 诚实边界（limitations 直接可用）

1. **人类金标非独立双标**：BEA 与 MRBench 同血统（1,493 条共享回复一致率
   1.000），给不出人类-人类 kappa 天花板；只能引用原论文标注者一致性 +
   用三票分歧率（bea 0.393）佐证噪声占比。
2. **金标全是英文数学 tutoring**：进化出的 rubric 对中文、其他学科未验证；
   中文双标冲刺（300–500 条）是已登记的缺口。
3. **裁判样本 3 个**（M3 + glm-5.2 + deepseek-v4-pro，§6.2），"方法普适"
   已从观察升为模式；但 test 终验只有 glm 一家做过（test 只能开封一次），
   M3/dsv4 的验收 rubric 均为 dev-only 证据。
4. **消融是降预算版**（每线 3k 调用 ≈ 全方法第 1 轮的量；降预算对对照组
   有利，不削弱结论，但全预算复现留待 `--budget 0`）；P5/P6 成分的单独去除
   消融没跑，其必要性由 GEPA 劣化与 winner's curse 系列间接支撑。
5. **test 只能开封一次**：塌方根因分析（test 更干净）是事后观察，
   无法再实验验证；同理，§6.1 纯 M3 自举的验收 rubric 只有 dev 证据
   （test 已在实验七用掉）。
6. glm 的 test 存活率 1/3 本身就是论点：**没有 test 终验的 rubric 优化
   结果不可信**——这条既是 limitation 也是卖点。
