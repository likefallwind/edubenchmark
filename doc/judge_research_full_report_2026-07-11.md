> 时间跨度：2026-07-06 → 2026-07-10，共 7 个实验阶段。

> 最后给出论文可主张的贡献点与对应证据。
> 数据/脚本索引见文末；过程细节在 `doc/judge_research_plan_2026-07-06.md` 与

## 0. 研究问题与动机

本仓库的教学能力评测（MRBench / BEA 2025 / MathTutorBench 等 C4 深测）大量依赖
**LLM 裁判**给 tutor 回复打教学维度标签（如 Providing_Guidance、Coherence）。
这带来三个必须回答的问题：

1. **裁判可信吗？** 裁判与人类专家标注的一致性（Cohen's kappa）是多少？
   哪个模型当裁判最好？有没有系统性偏置（偏严/偏宽/偏爱长回复）？
2. **怎么让裁判更准？** 堆裁判（多裁判投票的"陪审团"）有用吗？
   还是应该优化裁判的 rubric prompt？如果优化 prompt，怎么防止过拟合？
3. **优化出的收益是真的吗？** dev 上显著的提升，在封存的 test 上还在吗？
   ——这决定了什么能上生产。

与文献里多数"无人类标注、靠 meta-judge 自举"的裁判优化工作不同，我们手里有
**≈2.4 万条人类金标判例**（dev ≈1.8 万）。这把问题变成一个**有监督的 prompt
优化问题**，而且诊断信号（偏严方向、分歧率、长度偏置）能指明搜索方向——
这是整条研究线的方法论支点。

## 2. 实验一：元评测集 `data/judge_meta_eval_v1/`

**为什么做**：要回答"裁判可信吗"，必须有一个固定的、防泄漏的人类金标测试面。
仓库里的人类标注散在三个 benchmark 的源数据里，item_id 是位置式的，且
BEA dev 与 MRBench V2 有 **182 个对话精确重叠**——直接混用会造成 split 内部泄漏。

**怎么做**（`scripts/build_judge_meta_eval.py`，幂等、byte 级确定）：

- 三个来源、两种任务类型，**不强行统一标签空间**：
  - mrbench：13,240 条 dimension_label（1,655 个 (对话×回复模型) × 8 教学维度）；
  - bea2025：9,904 条 dimension_label（2,476 回复 × 4 维）；
  - mathtutorbench：964 条 pairwise 偏好（482 专家偏好对 × ab/ba 两序）。
- **切分单元 = 对话**（不是 item）：一个对话的所有判例（跨来源、跨维度、跨回复模型）
  整体进同一 split；182 个重叠对话只判一次归属。dev/test ≈ 75/25，
  固定种子 + (来源×维度×标签) 贪心分层。
- 配套基建：harness 加 `--item-list`（按清单跑）；所有裁判 adapter 声明
  `JUDGE_PROMPT_VERSION` + prompt sha256（改 rubric 必须 bump 版本，全程可归因）；
  公共统计模块 `scripts/eval/stats.py` —— **cluster bootstrap 95% CI，
  重采样单元 = 对话**（同一对话下多个判例高度相关，按 item 重采样会低估方差），
  以及同一重采样序列上的**配对差值 CI**（一切"A 是否显著优于 B"的裁决标准）。

**结果**：24,108 条（test 3,336 / 2,492 / 240），validate 全过，重跑 byte 一致。
一个重要的诚实声明：BEA dev 标注与 MRBench V2 在 1,493 条共享回复上一致率 1.000
——它们是**同一血统的复制**而非独立双标，所以没有免费的人类-人类 kappa 天花板，
上限只能引用原论文 IAA 并用三票分裂率佐证。

**对论文的意义**：这是全部后续实验的实验面。"对话级切分 + 配对 cluster-bootstrap CI"
是后面每一个显著性声明的地基。

## 3. 实验二：陪审团 vs 最佳单裁判 + 偏置画像

**为什么做**：提升裁判质量最流行的工程手段是多裁判投票（jury）。在花力气优化
prompt 之前，先回答"堆裁判够不够"；顺带给每个裁判做偏置体检，为后续诊断提供方向。

**怎么做**：陪审团 = {deepseek-v4-pro, glm-5.2, MiniMax-M3}（三个不同家族）。
dsv4-pro 与 M3 的票复用已有全量输出（零新调用），补跑 glm-5.2 两格（≈9.8k 次，
unparsed=0）。投票规则写死：多数票（弃权/平票由 dev kappa 最高者 tie-break）+
dev-kappa 加权票。全部指标只在 test split 上算，n_boot=1000。

**结果**（`reports/eval/_judge_jury/`）：

1. **主判定：陪审团不显著优于最佳单裁判**。三条线 kappa 配对差值 CI 全含 0
   （mrbench +0.003 [−0.016, 0.019]；bea2025 +0.005 [−0.014, 0.023]；
   mathtutorbench −0.008）。glm 全量 dev 落地后用全量权重复跑，结论不变，封板。
2. **意外发现：glm-5.2 是最佳单裁判**（test kappa mrbench 0.438 / bea2025 0.406，
   超过 dsv4-pro 的 0.417 / 0.388）；**当时的生产默认裁判 MiniMax-M3 恰好垫底**
   （0.354 / 0.335）。
3. **偏置画像**：所有裁判在所有长度桶上都比人类**系统性偏严**
   （P(judge=Yes)−P(human=Yes) = −7~−21pp，多数显著；M3 最严）——主缺陷是
   校准错位而非"偏爱长回复"。但 pairwise 线上 **M3 显著偏爱更长回复**
   （P(选更长)=0.585 vs 人类 0.500，+0.085 [0.017, 0.154]）——教育场景
   "裁判偏爱看似更耐心的长回复"的风险在 M3 上实测成立。
4. 副产物：`disagreements.jsonl` 8,544 条三票分歧判例（含三家 rationale），
   三票分歧率 bea 0.393 > mrbench 0.309 > mathtutorbench 0.138——既是任务模糊度
   的量化，也是未来自训裁判的种子数据。

**对论文的意义**：负结果 + 方向修正。"堆裁判"这条最省事的路被显著性检验关掉，
提升只能来自 rubric 本身；同时"系统性偏严"这一诊断直接决定了下一步先做校准实验。

## 4. 实验三：Stage 0 校准地板

**为什么做**：既然主缺陷是"偏严"（边缘分布错位），这类误差未必需要昂贵的
prompt 进化——先用两个便宜手段探底，建立任何进化方法**必须显著超过的地板**，
并用决策门决定后续投入规模。

**怎么做**：

- **0a 后验标签重映射**（零 API）：对每个 (裁判, benchmark, 维度)，在 dev−评估片
  上枚举全部 `源标签→目标标签` 映射（≤81 个），选 dev kappa 最大者，在评估片上
  报告配对差值 CI。这是分类器 Platt scaling 的标签版——不改 prompt 的校准上界。
- **0b DPFS 锚例**（≈4k glm 调用）：每维度 K=6 个 few-shot 人类锚例，标签配比
  匹配 dev 人类边缘分布（锚例严禁来自评估片，脚本内断言）；`dpfs_cal` 再加一行
  显式边缘分布提示。

**结果**（评估片 mrbench 1,202 / bea2025 801，n_boot=1000）：

| 手段 | mrbench | bea2025 |
|---|---|---|
| 0a 重映射（glm） | 0.417→0.468（+0.050 显著） | 0.458→0.499（+0.041 显著） |
| 0b dpfs_cal（glm） | 0.417→**0.523**（+0.106 显著） | 0.458→**0.516**（+0.058 显著） |

- 学到的映射高度一致为 **"To some extent"→"Yes"**；M3 重映射后追平 glm 基线——
  M3 的"弱"大半是校准而非理解。
- **关键的维度级分化**：Tutor_Tone、Mistake_Location 等维度被锚例大幅修复
  （+0.16~+0.26），但 **Providing_Guidance 对两种校准手段都免疫**
  （0.383→0.400，重映射同样无效）——它是**语义缺口**维度；而近天花板的
  Revealing_of_the_Answer 反被锚例带偏回退（0.884→0.806）→ 后续必须
  per-dimension 门控。
- 0b 补跑期间踩了一个方法论上重要的坑：裁判调用误设 `max_tokens=1024` 饿死了
  ~17% 难题的回复，造成**留存子集选择偏差**（基线虚高）；去 cap 重跑后修正。
  此后"glm 裁判调用不设 max_tokens"成为硬规则。

**决策门判定**：校准手段吃掉的差距占比落在 20–60% 档（天花板取 κ=0.7 时
mrbench 37% / bea 24%）→ 按计划全量进入自进化阶段；残余差距
（Providing_Guidance / Coherence 等）需要**诊断驱动的语义编辑**。
另外实测到第一例 winner's curse（dsv4 一个映射在学习池赢、评估片输），
预告了后面反复出现的主题。

**对论文的意义**：这是消融表里的"地板"行，也是"校准 vs 语义"二分法的
证据来源——先把便宜的校准收益全部拿掉，剩下的才是 prompt 进化真正要挣的钱。

## 5. 实验四：rubric 自进化方法与 M3 pilot（Stage 1/2）

**为什么做**：Providing_Guidance 这类校准免疫维度只能改 rubric 语义。通用
prompt 优化器（GEPA 类反思式进化）在文献里有四个实锤缺陷：prompt 膨胀与
边例记忆、反思归因错误、噪声指标下选候选低效（winner's curse）、不优化锚例。
我们的方法（原则 P1–P6）逐条对症，另加两条独有设计：**P5 聚合诊断驱动提案**
（提案输入是分布级证据：混淆矩阵格、长度桶宽容度差，而非一小撮错例）与
**P6 共识分层去噪**（三家裁判全量票把判例分为三层，隔离"三票分裂=题目模糊"
的噪声信号）。

**方法核心**（`scripts/run_judge_rubric_stage1.py` + `build_judge_stage1_assets.py`）：

1. **结构化 rubric 表示**：`{维度定义, 每标签行为化判据, 边界澄清条款[], 锚例块}`，
   序列化时逐段渲染；空 rubric 的渲染与现行 adapter prompt **字节级一致**（断言），
   保证 v1 基线可复用缓存。
2. **类型化编辑算子**（6 种：add_anchor / edit_boundary / add_clause / drop_clause /
   swap_exemplar / edit_definition）——不允许自由文本整段重写，防膨胀防漂移。
3. **诊断驱动提案**：反思 LLM 的输入 = 该维度混淆矩阵 + 每格错例样本（带裁判
   自身 rationale）+ 长度桶宽容度，要求提案**针对特定混淆格**。
4. **两段制验收**：候选先在 ~150→250 条筛选片上排序淘汰，幸存者跑 ~600 条
   全量评估片，**配对 cluster-bootstrap CI 下界 >0 且 unparsed 不回退才接受**；
   已接受编辑每轮回归消融（边际效用转负则剔除）。
5. **数据三分防泄漏**：锚例池 / 诊断池 / 评估片互斥，test split 全程封存。
6. 工程化：响应级断点续跑、25 连败熔断、ledger 记录每条编辑的
   触发诊断→效应量→CI→prompt hash 完整审计链。

**Pilot 设定**：应成本考量先用 MiniMax-M3 当裁判（反思模型 glm-5.2），
靶维度 = Stage 0 后残余差距最大的 mrbench/Providing_Guidance、mrbench/Coherence、
bea2025/Providing_Guidance。

**结果**（3 轮，~25k 调用）：

- **唯一显著验收**：mrbench/PG 的 r1p3——一条边界条款"相关的引导性提问/提示即算
  Yes，不要求明确指出错误位置"，正对最大混淆格（human=Yes|judge=To some extent,
  77 例）。0.272→0.340，**+0.068 [0.011, 0.126] 显著**。同场对照：dpfs_cal 锚例
  在同维度只有 +0.007 ns——**"语义编辑修得动校准免疫维度"假设成立**。
- **Winner's curse 反复实测**（pilot 内 7 次）：筛选片第一名在全量片上翻车/转 ns
  成为常态；两个"近失"候选（CI 下界差 0.001 过线的 +0.055、+0.059）用
  **独立确认协议**（`run_judge_rubric_confirm.py`：放到选择过程从未接触的池子
  数据上重测，选择/确认数据分离）复验后**全部归零**（−0.002 / −0.001）——
  若当时放宽验收，两条无效编辑就进 rubric 了。**严格配对 CI 验收被独立数据背书。**
- Coherence 两轮 18 候选全灭（M3 平台 0.303）；重诊断后候选全负 → r1p3 是
  M3+提示编辑的局部最优。当时的定性是"残余差距主体 = 标注噪声"——
  这个定性后来被 glm 实验**修正**（见下节），是一个有教益的错误。
- 过程派生的方法升级（进入 Stage 2 规格）：**自适应重诊断**（每轮验收后用当前
  incumbent 在诊断池重打标再诊断——静态 v1 诊断的边际提案质量会衰减）、
  筛选片 157→250、反思提示携带 ledger 战绩（禁止重复失败思路）。

**对论文的意义**：方法本体 + 三层防过拟合（筛选/验收数据分离、配对 CI 门、
独立确认）的必要性证据。pilot 的主要产出不是那 +0.068，而是**被 7 次
winner's curse 实测证明必要的验收纪律**。

## 6. 实验五：glm-5.2 主实验

**为什么做**：协议规定方法定稿后迁移到最佳单裁判 glm-5.2。这一轮同时检验两件事：
方法是否普适（换裁判还有效吗），以及缺陷是否裁判特异（M3 学到的条款能不能搬）。

**怎么做**：同一套 Stage 2 完整规格（--big-screen --rediagnose），裁判与反思
模型均为 glm-5.2；状态目录按裁判隔离（`stage1_glm-5.2/`），评估片滑片与 M3
byte 级相同（同种子复用），诊断用 glm 缓存的 v1 全量跑重建（零增量调用）。

**起点画像先给出可证伪预测**：glm 的主混淆格是 human=**TSE→judge=No**（偏严），
与 M3 的 TSE→Yes（偏宽）**方向相反**——所以 M3 验收的 r1p3 不应假设可迁移，
glm 的反思看 glm 自己的错例。

**结果**（3 轮，~22k 调用，4 条验收）：

| 线 | v1 → 终版（评估片 κ） | 累计增益 | 验收编辑 |
|---|---|---|---|
| mrbench/Providing_Guidance | 0.322 → **0.438** | **+0.116** [0.055, 0.174] | r1p2：TSE 行为化判据"试图引导但误诊/有瑕疵 → TSE 非 No" |
| bea2025/Providing_Guidance | 0.392 → **0.484** | **+0.092** [0.028, 0.163] | r1p1：定义改写 + 同判据 |
| mrbench/Coherence | 0.268 → **0.400** | **+0.132**（两轮两验收） | r1p3 + r2p1："纠错/重读题目/换步骤建议是连贯教学回应，不判 No/TSE" |

四个发现：

1. **方法完全迁移，条款完全不迁移**：glm 的验收编辑全部修 TSE→No 偏严，
   与 M3 修的方向相反——起点画像的预测被证实。**rubric 进化必须按裁判跑，
   诊断驱动是方法有效的原因而非装饰。**
2. **收益是 M3 的 3~5 倍**（4 条验收 vs 1 条）：更强的裁判对 rubric 语义的
   响应能力更强——"用弱裁判省成本"在进化收益上是假节省。
3. **M3 pilot 的"标注噪声天花板"定性被修正**：Coherence 在 M3 手里 18 候选全灭，
   在 glm 手里两轮验收 +0.132——那是 M3 的能力平台，不是任务不可修。
   "残余差距=噪声"的定性必须按裁判分别下。
4. 校准手段继续陪跑（dpfs_cal 三线全 ns、remap 叠加恒等或负）；平台出现在
   第 2~3 轮；近失 r3p3 独立确认再次缩水（累计第 8 例 winner's curse）——
   pilot 的全部方法论结论在第二个裁判上复现。

## 7. 实验六：消融基线（收益到底来自哪）

**为什么做**：+0.116/+0.092/+0.132 也可能"随便怎么搜都能搜出来"。消融要回答：
收益来自**诊断驱动 + 显著性门控**，还是来自搜索宽度、文本自由度或人工经验？

**怎么做**（`scripts/run_judge_rubric_ablation.py`）：三条主实验线上跑三个参照
基线，**共享全方法的全部 infra**（渲染/断点续跑/配对 CI），评估片、判官、打分
与主实验逐字节一致——唯一的差别是"候选如何提出/挑选"：

- **手工 J2b**：人工精心写的 rubric（行为化标签锚点 + "判前先想理想教学动作"），
  但**盲于诊断**；
- **生成-K-选优**：LLM 自由生成 K=5 套规则，按评估片 κ 挑最优（故意放水的
  乐观上界——正常应在 held-out 上挑）；
- **GEPA 原味**：反思式整段自由文本重写 + val 贪心接受，无显著性门控
  （文献里最强的通用 prompt 优化基线）。

预算 3,000 次/线（≈全方法第 1 轮生产性搜索的量，收益大头正是在第 1 轮拿到的；
降预算对基线有利，不削弱结论）。

**结果**（Δκ vs v1，95% 配对 CI）：

| 方法 | mrbench/PG | bea/PG | mrbench/Coherence | 显著数 |
|---|---|---|---|---|
| 手工 J2b | +0.032 ns | +0.010 ns | +0.034 ns | 0/3 |
| 生成-K-选优 | −0.001 ns | +0.005 ns | +0.029 ns | 0/3 |
| GEPA 原味 | +0.054 ns | **−0.126 显著劣化** | +0.048 ns | 0/3 |
| **全方法（P1–P6）** | **+0.116 ✓** | **+0.092 ✓** | **+0.132 ✓** | **3/3** |

三个基线的失败模式互不相同（这正是消融想要的）：

1. **手工**：写得规整但不知道往哪改 → 噪声级漂移。人工设计的上限不在文笔，
   在"知道病灶在哪个混淆格"。
2. **生成-K**：即便按乐观上界挑，最优只 +0.03；K 个候选的 κ 分布整体贴着或
   低于 v1。**加大搜索宽度救不了无方向搜索。**
3. **GEPA（最有说服力）**：三线冠军在自己的 val 上 κ 0.542/0.594/0.690，
   全都比全方法"漂亮"——落到评估片崩到 0.265/0.376/0.316，bea/PG **显著
   跌破 v1**。自由文本重写 + 无显著性门控 = 把 val 噪声当信号。这把全方法
   坚持配对 CI 验收门的理由从设计信念变成了**实测证据**。

## 8. 实验七：Stage 3 test 终验 + 生产切换

**为什么做**：dev 上的一切显著性——哪怕过了配对 CI、回归消融、独立确认——
仍然是"对 dev 标注分布"的结论。封存的 test split 是唯一能区分
"对 dev 分布的真提升" vs "对任务的真提升"的手段。协议规定 test 人类金标
**首次也是唯一一次**在此被触碰。

**怎么做**（`scripts/run_judge_rubric_stage3.py`）：test 片上跑 v1 与进化 rubric，
各自 vs 人类金标算 κ + 配对 CI；发车前硬断言 test 与 dev 的评估片/池/对话簇
零重叠（全过）；进化 rubric 皆类型化编辑、无锚例 → 零泄漏。glm 三条终版 +
M3 pilot 的 r1p3 一起上。

**结果：4 条线 2 条存活，且都在同一个维度上**：

| 线 | 裁判 | v1(test) | 进化(test) | test Δ | 95% CI | dev 曾经 | 复现 |
|---|---|---|---|---|---|---|---|
| mrbench/PG | glm-5.2 | 0.394 | **0.508** | **+0.115** | [+0.049, +0.185] | +0.116 ✓ | **✅** |
| mrbench/Coherence | glm-5.2 | 0.430 | 0.431 | +0.002 | [−0.080, +0.110] | +0.132 ✓ | ❌ |
| bea2025/PG | glm-5.2 | 0.477 | 0.465 | −0.012 | [−0.081, +0.056] | +0.092 ✓ | ❌ |
| mrbench/PG | MiniMax-M3 | 0.315 | **0.389** | **+0.074** | [+0.009, +0.137] | +0.068 ✓ | **✅** |

**为什么两条塌了——第二层过拟合**。关键观察：v1 在 test 上本就明显高于 dev
（Coherence 0.268→0.430、bea/PG 0.392→0.477）——test 片更干净（标注噪声小）。
进化编辑修的是 dev 诊断里的特定偏严模式：

- mrbench/PG：该模式在 test 上依然存在 → 编辑修到**任务级真病灶** → 干净复现；
- Coherence / bea/PG：dev 病灶在干净的 test 上本就不明显 → 编辑修的是
  **dev 特有噪声** → test 上无物可修，归零。

这是配对 CI 门控**原理上拦不住**的过拟合层级：dev 上的提升是真实、可复现的
（不是选择噪声），但它是对 dev 标注分布的真提升，不是对任务的。至此全流程
共辨析出**两层性质不同的过拟合**：

| 层 | 现象 | 谁能拦住 | 实测证据 |
|---|---|---|---|
| ① 选择噪声（winner's curse） | 筛选/验收边界上的候选换数据就归零 | 筛选-验收数据分离 + 配对 CI + 独立确认 | 累计 9 例（pilot 7 + glm 1 + GEPA 1） |
| ② dev 分布特异性 | dev 显著、可复现的提升在 test 上塌零 | **只有封存 test 终验** | glm 3 线中 2 线（Coherence、bea/PG） |

**最稳健的正结果**：mrbench/Providing_Guidance 被**两个裁判各自独立进化**
（修的还是相反方向的缺陷表现）、**双双通过 test 门**——"引导性提问应算 Yes /
对部分正确引导过度降级"是该维度**任务级的真实 rubric 缺口**，跨裁判稳健可修。
M3 pilot 也因此净成果非零（1 条经 test 验证的真提升）。

**生产切换**（用户拍板，2026-07-10 已落地进代码）：

- **③a 换判官**：`mrbench.py` + `bea2025.py` 的 `DEFAULT_JUDGE_MODEL`
  M3→glm-5.2。证据来自元评测（glm 是这两条 dimension-label 线的最佳单裁判），
  与 rubric 结果无关、独立成立。**范围仅这两条**——mathtutorbench（pairwise，
  无 glm 最佳证据）、mmtutorbench（多模态）、eduguard（安全）未进元评测，
  一律不动，盲切无证据支撑。
- **③b 换 rubric v2，仅 mrbench/PG**：`_evolved_judge_prompt` 把 r1p2 的
  TSE 标签准则注入**仅 tutor 生产判官**；经断言与 test 上验证的渲染
  **byte 完全一致**（上生产的 == 验证过的）；`PRODUCTION_JUDGE_PROMPT_VERSION="v2"`
  + provenance 记录。`mrbench_judge` 校准基准保持 v1（它测被测模型的判官能力，
  prompt 不能漂）；Coherence 与 bea/PG 留 v1（dev 增益未过 test，不上生产）。

## 9. 论文铺垫：可主张的贡献点与证据

### 9.1 核心故事线（建议的论文骨架）

> **"有人类金标监督时，教学裁判的 rubric 应该怎么优化、怎么验收"**——
> 一个诊断驱动、显著性门控、test 终验三层设防的自进化框架，
> 以及它揭示的两层过拟合结构。

1. **动机**：LLM 裁判在教育评测中大规模使用，但与人类专家的 kappa 只有
   0.3–0.44；陪审团（多裁判投票）被显著性检验证明无效（§3）→ 提升必须来自
   rubric 本身。
2. **诊断**：系统性偏严是主缺陷；校准手段（重映射/锚例）能吃掉 20–60% 差距，
   但关键教学维度（Providing_Guidance）对校准免疫（§4）→ 语义缺口存在。
3. **方法**：结构化 rubric + 类型化算子 + 聚合诊断驱动提案 + 两段制配对 CI 验收
   + 独立确认（§5）。
4. **主结果**：双裁判实验（§5/§6）——方法迁移、条款不迁移（缺陷裁判特异）；
   强裁判进化收益 3~5 倍。
5. **消融**：手工/生成-K/GEPA 三基线同 infra 同预算 9 格零显著、GEPA 显著劣化
   （§7）→ 收益归因于"诊断驱动 + 显著性门控"两个组件。
6. **终验与两层过拟合**（§8，本文最有区分度的发现）：dev 显著 ≠ 任务级真提升；
   配对 CI 拦得住选择噪声（9 例实测）、拦不住 dev 分布特异性（2/3 塌方）；
   唯一双裁判双验的维度给出"任务级 rubric 缺口"的存在性证明。
7. **落地**：证据分级的生产切换纪律（每条线独立 test 验收，不整批上）。

### 9.2 贡献点 → 证据对照表

| 可主张的贡献 | 支撑证据 | 强度 |
|---|---|---|
| 陪审团对教学裁判无显著收益（负结果） | 三线配对 CI 全含 0，全量权重复跑封板 | 强（预注册式判定标准） |
| 教学裁判系统性偏严 + M3 长度偏置 | 全裁判全长度桶 −7~−21pp；M3 pairwise +8.5pp sig | 强 |
| 校准/语义二分：校准地板 + 免疫维度 | 0a/0b 六格显著 vs PG 免疫（+0.017 ns） | 强 |
| 诊断驱动+显著性门控的自进化框架有效 | 双裁判 5 条显著验收；同预算三基线 0/9 | 强（消融闭合） |
| 缺陷是裁判特异的（方法迁移、条款不迁移） | M3 修 TSE→Yes、glm 修 TSE→No，方向相反且各自起点画像预测在先 | 强 |
| 两层过拟合的辨析与实测 | 9 例 winner's curse + glm 2/3 test 塌方 + 根因分析（test 更干净） | 强，且新颖 |
| mrbench/PG 存在任务级 rubric 缺口 | 双裁判独立进化、双双过 test（+0.115 / +0.074，双显著） | 最强的单点结果 |
| "弱裁判省成本"是假节省 | glm 4 验收 vs M3 1 验收；Coherence 平台被证明是 M3 能力问题 | 中强（两个裁判的对比，n=2） |

### 9.3 诚实边界（论文 limitations 就写这些）

1. **人类金标非独立双标**：BEA 与 MRBench 同血统（1,493 条一致率 1.000），
   无法给出人类-人类 kappa 天花板；只能引用原论文 IAA + 三票分裂率
   （bea 0.393）佐证噪声占比。
2. **全部金标是英文数学 tutoring**：进化出的 rubric 对中文/其他学科未验证；
   中文双标冲刺（300–500 条）是已登记的缺口。
3. **裁判样本 n=2**（M3 + glm-5.2；dsv4-pro 复验未跑）："方法普适"的外推有限。
4. **消融是降预算版**（3k/线 ≈ 全方法第 1 轮；全预算 `--budget 0` 可复现），
   且 P5/P6 的 2×2 去除消融未单跑——其必要性由 GEPA 劣化与 winner's-curse
   系列间接坐实，论文里如实写间接。
5. **test 只能碰一次**：Coherence/bea 的"塌方根因"分析是事后观察
   （v1 test 高于 dev），不是再实验验证。
6. glm-5.2 的 test 存活率 1/3 本身说明：**没有 test 终验的 rubric 优化结果
   不可信**——这条既是 limitation 也是卖点。

### 9.4 建议补的实验（如果要投稿）

按性价比排序：

1. **dsv4-pro 复验**（协议里本就预留）：把裁判 n=2 变 n=3，"方法迁移"从
   观察变成模式，≈15k 调用。
2. **P5/P6 的 2×2 消融**：把间接证据变直接，补齐消融矩阵最后两行。
3. **v2 rubric 的下游影响**：mrbench_tutor 用 v1/v2 judge 各跑一遍同一批被测
   模型，报告 pedagogical pass rate 的排序稳定性——把"裁判 κ 提升"连到
   "评测结论是否改变"，这是评测论文审稿人必问的。
4. 中文小规模双标 + 迁移测试（大工程，可作为 future work）。
